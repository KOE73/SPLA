# SPLA Architecture Tool (`spla-arch`) — Agent Guide

Детерминированная Go-утилита: извлекает сущности из C#, раскладывает их по
правилам заданной точки зрения и **проверяет**, что схема, правила и код
по-прежнему сходятся.

## Философия

По Доктрине SPLA: **интеллект — из модели в детерминированный инструмент.**
Модель не должна каждый раз перечитывать сотни `.cs` и заново изобретать, что
куда положить. Классификация делается один раз, записывается в файл правил и
дальше применяется машиной.

Роль агента сужается до одного: **разобрать то, что инструмент отложил.**

## Контракт

Инструмент принимает тройку и отвечает на один вопрос — всё ли сходится:

```
   список сущностей (из кода)
 + правила точки зрения (mapping)          →   ничего не сломано?
 + json-схема                                  нет лишнего? не хватает?
```

Выход — список находок трёх видов. Его читает агент и правит **либо правила,
либо схему** (код не правится ради схемы):

| Вид | Что значит | Обычная причина |
|-----|-----------|-----------------|
| `сломано` | схема сама себе противоречит | связь в никуда, узел вне своей зоны, дубль сущности, перекрытие зон |
| `лишнее` | на схеме есть то, чего нет в коде | тип переименован/удалён, дерево исходников переехало, правило указывает в пустоту |
| `не хватает` | код есть, а на схеме его нет | новый тип, который ни одно правило не забрало |

## Три слоя, которые нельзя смешивать

1. **Извлечение** (`parser/`) — что вообще существует. Автоматика, знания о
   смысле нет.
2. **Правила** (`docs/diagrams/mapping/<точка-зрения>/*.map.json`) — что это
   значит. Единственный рукописный артефакт; по сути кэш принятых решений,
   чтобы не изобретать классификацию заново.
3. **Раскладка** (`layout/`) — координаты. **Производные.** В сгенерированной
   схеме их нельзя править руками: следующий `build` перезапишет. Долговечен
   файл правил, а не координаты.

Наборы правил — свои на каждую точку зрения: `semantic-atlas` один набор,
`message-flow` другой. Смысл группировки у них разный, общего набора не бывает.

## Команды

Рабочий каталог: `tools/spla-arch`

### build — перегенерировать атлас по правилам

```bash
go run . build --mapping ../../docs/diagrams/mapping/semantic-atlas/core.map.json --repo ../.. --out ../../docs/diagrams/model-core-full.json
```

Пишет схему и обновляет lock-файл `<id>.known.json` — снимок «где что лежало в
прошлый прогон». Разница с ним и даёт ответ, что появилось с тех пор, как на
схему последний раз смотрел человек.

### verify — проверить, что всё сходится

```bash
go run . verify --dir ../../docs/diagrams --repo ../..
```

Ничего не пишет. Проверяет и сгенерированные, и рукописные схемы. Выход `1`,
если есть что решать. Полноту требует **только** от `semantic-atlas`: у
`message-flow` неполнота — это замысел, а не дефект.

### check — build вхолостую, для хука или CI

```bash
go run . check --mapping ../../docs/diagrams/mapping/semantic-atlas/core.map.json --repo ../..
```

### parse / layout — старый путь без правил

`parse` строит сетку по namespace. Это [антивариант](../../docs/diagrams/README_RU.md):
годится как разовая разведка нового поддерева, но не как схема, которую держат.

## Правила разрешения (в порядке приоритета)

1. **`match.name`** — точное имя типа. Для тех, чей смысл не выводится из
   расположения.
2. **`match.nameRegex`** — регулярка по имени.
3. **`match.path`** — префикс пути, побеждает самый длинный. Именно это делает
   инструмент автоматическим: новый файл в известной папке разложится сам.
4. **Сосед по файлу** — тип из файла, чей главный тип уже размещён, наследует
   его блок. Один файл — одна единица смысла.
5. Всё остальное — в оранжевую зону `НЕ РАЗМЕЩЕНО` на холсте. Это очередь работы.

## Что инструмент считает не-архитектурой

- `private` и `protected` вложенные типы — деталь реализации.
- `bin/`, `obj/`, `*.g.cs`, `*.Designer.cs`, `AssemblyInfo`, `GlobalUsings`.

## Виды связей

Два семейства, различимые с одного взгляда (словарь — в `index.html`,
`EDGE_STYLES`):

- **Структура**, извлекается автоматически: `extends` (полый треугольник),
  `implements` (сплошной треугольник), `composes` (ромб).
- **Потоки**, описываются руками в `<id>.edges.json`: `call`, `data-flow`,
  `event`, `security`, `storage`. Намерение рантайма не видно в объявлении
  типа, поэтому автоматически его не извлечь.

Файл потоков может ссылаться на типы по имени (`"from": "ChatManager"`), id
подставится сам.

## Правила для агентов

- **Не править руками** файл с `metadata.generated: true` — правь `.map.json`
  и перегенерируй.
- **Не расширять** правило `path` шире, чем папка на самом деле однородна:
  широкое правило молча утащит новые типы не туда. Лучше пусть отложит.
- При изменении JSON-контракта схем — синхронно обновить `model/diagram.go`
  и `index.html`.
