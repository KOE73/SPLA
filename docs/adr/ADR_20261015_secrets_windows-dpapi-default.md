# Windows: DPAPI по умолчанию и отказ от отката к открытому хранению

Статус: принято.

Заменяет решение об умолчаниях и допустимости отката из
[`ADR_20260712_secrets_store-and-ssh`](ADR_20260712_secrets_store-and-ssh.md).
Остальные решения того ADR сохраняются.

## Причина

Открытое хранение по умолчанию позволяло обычному Windows-запуску сохранять пароли без шифрования.
При недоступности выбранного DPAPI загрузчик также переходил к открытому YAML с предупреждением.
Выбор шифрования тем самым не гарантировал, что секреты действительно будут зашифрованы.

## Решение

- Без `secrets.backend` Windows выбирает DPAPI (`CurrentUser`), остальные ОС сохраняют `file`.
- Открытый `file` остаётся доступен на Windows только при явном выборе в машинном `defaults.yaml`.
- Недоступный выбранный бэкенд, неизвестное или явно пустое имя завершают загрузку настроек ошибкой.
  Ошибка фабрики также передаётся вызывающему коду. Отката к другому хранилищу нет.
- CLI и настольная оболочка регистрируют фабрику DPAPI до загрузки настроек. Сервер сохраняет
  независимость от платформы при компиляции: сборка DPAPI поставляется как отдельный артефакт
  и загружается на Windows при запуске.
- Области, имена записей, права доступа и формат ссылок не меняются. Автоматическая миграция
  открытых файлов не добавляется: старый файл не читается вместо выбранного шифрованного.

## Следствия

Windows-хост, встраивающий рантайм, обязан зарегистрировать DPAPI до разрешения настроек либо явно
выбрать `file` в изолированном машинном слое разработки. Ошибка конфигурации останавливает запуск,
даже если текущая операция ещё не использует пароль. Это исключает неожиданную запись без шифрования.

DPAPI защищает значения на диске под учётной записью Windows; процесс с той же учётной записью
может их расшифровать. Перенос файлов к другому пользователю не заменяет миграцию секретов.
