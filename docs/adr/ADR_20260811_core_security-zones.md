# ADR_20260811_core — зоны, рёбра и гранты: модель безопасности

Статус: **принято**

Ход работ: [`PLAN_20260811_core_security-zones`](../plans/PLAN_20260811_core_security-zones.md).
Песочница для `Execute` живёт отдельно: [`PLAN_20260807_host_sandbox`](../plans/PLAN_20260807_host_sandbox.md).

Решение о том, как SPLA понимает «куда агенту можно»: зоны вместо одной оси `ToolScope`, вызов как
ребро между зонами вместо точки, гранты на ребро вместо грантов на вызов.

Legacy нет — правила меняем целиком, миграций не делаем.

---

## 1. Контекст

Разбор начался с малого — «привязать файловые инструменты к корню проекта» — и упёрся в то, что
привязывать некуда: модель разрешений не различает того, что нужно различать.

Что нашлось при разборе:

- **`ToolScope` смешивает «где» и «как».** `Project`, `Local`, `Internet` — это места;
  `Shell`, `Skill`, `Agent` — способы и субъекты. Одна ось на два вопроса.
- **У вызова не одно место, а два.** `browser_upload` читает файл с диска и отправляет его в
  веб-форму; объявлен `Scope = Internet, Effect = Write`
  (`src/plugins/SPLA.Plugins.Browser/Tools/BrowserUploadTool.cs:31`). Утечка классифицирована как
  «интернет-запись» и в режиме `Agent` проходит без вопроса.
- **Для «острова» клетки не было вовсе.** Все SQL-инструменты объявлены `ToolScope.Local`
  (`src/plugins/SPLA.Plugins.Sql/Tools/SqlQueryTool.cs:36`) — запрос к боевой базе на другом сервере
  числится локальным файловым доступом. Не описка: подходящего значения в перечислении нет.
- **Ось `Project` / `Local` уже разведена по режимам и уже мертва.** `PermissionManager`
  (`src/core/SPLA.MCP.Core/Permissions/PermissionManager.cs:131-196`) различает их во всех четырёх
  рабочих режимах, но `Scope` объявлен статически на инструменте, поэтому запись в `C:\Windows`
  проходит как «project write».
- **Единица запоминания бесполезна.** Грант матчится по имени инструмента и побайтово равному JSON
  аргументов либо по `*` (`PermissionManager.cs:117`). Первое не повторяется, второе слишком широко —
  отсюда усталость и массовое «разрешить всё».
- **Границы уже написаны четырежды и по-разному**: `LocalTarget.Resolve` (SFTP),
  `IsUnder` (скиллы), `ResolveWorkspacePath` (1С), `IsUnderRoot` (`WorkspaceOps`). Причём человек
  через веб-клиент за корень выйти не может, а агент может — ограничение стоит на самой безопасной
  поверхности и отсутствует на самой опасной.

## 2. Принятые решения

| Решение | Обоснование |
|---|---|
| Зона — место, а не способ | Один вопрос на одну ось; `Shell` перестаёт притворяться местом |
| Вызов — ребро «источник → приёмник» | Единственная форма, в которой выразима утечка: приёмник задаёт ущерб, источник — доверие |
| Остров = экземпляр соединения, не класс | Человек соглашается на конкретную ситуацию; грант шире данного обещания — это враньё, после которого доверие к системе кончается |
| Корень проекта = каталог манифеста, без вариантов | Второе определение (`workspace:`) уводило корень в сторону и никогда не делалось абсолютным |
| `.spla/` закрыт целиком — и от агента, и от git | Это рабочая папка «железа»: секреты, чаты, гранты, учёт. Нужно рядом — клади рядом |
| Пол на узле и правила на ребре — два механизма, не один | Настройка сервера и выгрузка туда зарплат — разные вещи при одном приёмнике; различает их источник |
| Метка происхождения на блобах и записях KV | Данные, отсоединённые от источника, теряют уровень доверия; без метки периметр течёт по самому тихому каналу |
| Флаг недоверия чата — один бит, монотонный, вне контекста | Уровни требуют порядка, который никто не назначит честно; всё, что в контексте, модель может переспорить внедрённым текстом |
| Флаг поднимает только неназванный источник | «Может ли в тексте быть промпт» — признак, по которому недоверенно всё; константа не несёт информации |
| Грант выдаётся на ребро | Осмысленных рёбер в живом проекте десятки, вызовов — тысячи; только на ребре грант переиспользуется |
| Гранты в `.spla/grants.yaml` | Не едут в git, не видны агенту, привязка к проекту даром |
| Карта зон — редактор политики, а не иллюстрация | Политику, которую надо писать текстом, никто не пишет (урок SELinux) |
| Сначала теневой режим, потом исполнение | Список законных исключений нельзя угадать, его можно собрать |

## 3. Топология

Две разные связи, которые нельзя смешивать:

- **вложенность** — «физически внутри»: проект внутри машины, вырез `.spla/` внутри проекта;
- **достижимость** — «только через учётку»: остров не вложен ни во что и достижим лишь по
  настроенному соединению.

```
┌─ Машина ───────────────┐        Острова (по учётке):
│  ┌─ Проект ─────────┐  │          LLM: <соединение>
│  │  ┌─ .spla/ ───┐  │  │          SQL: <соединение>
│  │  │  вырез     │  │  │          SSH: <хост>
│  │  └────────────┘  │  │          MCP: <сервер>
│  └──────────────────┘  │          Интернет  ← остров без учётки и без имени
└────────────────────────┘
                 Контекст ← труба, не хранилище
```

**Зона острова — экземпляр.** `SQL: prod` и `SQL: test` — разные зоны. Ключ гранта — отпечаток
существенных полей (адрес, база, порт, учётка). Переименование не наследует прав; смена сути гасит
грант.

> **Уточнено при реализации (2026-08-12).** Здесь планировался «устойчивый идентификатор **плюс**
> отпечаток». Отдельного идентификатора не потребовалось: оба нужных свойства даёт сам отпечаток.
> Переименование сути не меняет, поэтому грант переживает его; перестановка имён местами ничего не
> передаёт, потому что каждая запись остаётся при своей сути; репойнтинг суть меняет, поэтому грант
> гаснет. Явный `id` понадобился бы ровно для одного — чтобы грант **пережил** сознательный переезд
> сервера, а это как раз случай, когда переспросить правильно. Поля в конфигурациях не заведены,
> миграции нет. Реализация: `SPLA.Domain/Security/IslandIdentity.cs`.
>
> Два решения внутри отпечатка, которые стоит помнить: регистр значений **не** сворачивается (спутать
> два острова хуже, чем переспросить из-за смены регистра хоста), и секрет в отпечаток не попадает —
> учётка вносит имя записи или схему ссылки, но не значение, потому что отпечаток лежит в файле
> грантов открытым текстом.

**Контекст — не хранилище, а труба.** Всё вошедшее уезжает на остров провайдера, поэтому
«прочитать файл» — это ребро `Проект → LLM: <соединение>`, и его цена зависит от того, какой это
остров: локальная модель и облако — разные зоны. Отсюда три следствия, которых иначе не видно:

1. один и тот же вызов получает разный вердикт при смене модели;
2. данные могут переехать между островами через блоб, вовсе не побывав у провайдера;
3. **смена модели посреди чата — сама по себе передача**: весь накопленный контекст уезжает на
   новый остров одним ходом. Сегодня это бесплатная операция в выпадающем списке.

## 4. Ребро как единица решения

Приёмник задаёт ущерб, источник — доверие. Одной осью это не выражается, поэтому решение принимается
по паре.

| Ребро | Что это | Как оценивается сегодня |
|---|---|---|
| `Машина → Интернет` | утечка | обычная «интернет-запись», в `Agent` — без вопроса |
| `Проект → Интернет` | публикация своего | так же |
| `Интернет → Проект` | внесение недоверенного | обычная «project write» |
| `SQL: prod → SSH: web-01` | вынос данных на сервер | «write», без различения источника |
| `Проект → SSH: web-01` | настройка сервера | «write», без различения источника |
| `* → LLM: <соединение>` | чтение = выгрузка провайдеру | не моделируется вовсе |

Последние две строки — тот самый случай, ради которого модель и заводится: приёмник один, обе зоны
доверенные, а смысл противоположный.

## 5. Два механизма: пол на узле, правила на ребре

`allow_write` на SSH-хосте (`src/core/SPLA.Ssh.Core/SshSettings.cs:54`) отвечает на вопрос об одном
узле: можно ли вообще менять состояние этого острова. Правила зон отвечают на вопрос о паре: откуда
приехало то, что туда едет. Разная арность — значит разные механизмы.

- **Пол.** Остров помечен только для чтения → в него не идёт ни одно ребро, откуда бы ни пришло.
  Существующий `allow_write` остаётся как есть, править его не нужно.
- **Правила.** Работают выше пола и различают источник.

Сознательное упрощение: смена состояния (`systemctl restart`) и выгрузка содержимого
(`sftp_upload`) считаются одним эффектом — записью. Различать их дороже, чем польза.

## 6. Метки данных и флаг чата

**Происхождение на блобе.** `BlobEntry` несёт зону, из которой налит. Потребление блоба оценивается
как ребро `origin → приёмник`, а не `Agent → приёмник`. При слиянии нескольких входов выигрывает
наименьшее доверие — это правило нижней границы из модели целостности Бибы.

**Происхождение на записи KV.** `agent_memory_set(scope=project)` пишет в хранилище, общее для всех
чатов проекта (`src/core/SPLA.MCP.Core/Tools/AgentMemorySetTool.cs:15`). Без метки это прачечная:
заражённый чат кладёт туда недоверенный текст, свежий чат читает его с чистым флагом. Запись несёт
бит происхождения; чтение грязной записи поднимает флаг читателя.

**Флаг чата.** Одно поле в состоянии сессии — не в контексте: всё, что лежит в контексте, модель
читает как текст, и внедрённая со страницы инструкция может объявить его устаревшим.

Свойства флага:

- монотонный: только вверх, вниз не идёт;
- не сбрасывается ничем автоматическим — ни чекпойнтом, ни откатом, ни перезагрузкой; снять его
  может только человек кнопкой (см. ниже);
- наследуется под-агентами (спавн уже наследует песочницу, тот же провод);
- ложится в историю чата рядом с сообщениями, иначе перезагрузка обнуляет монотонность;
- виден в интерфейсе — невидимый флаг бесполезен.

**Признак — не «может ли в тексте быть промпт», а «назвал ли этот источник оператор».** Первый
признак негоден: заражённый текст может прийти откуда угодно — из файла на вашем SSH-хосте, из
строки, которую вернула ваша же хранимая процедура. Если считать недоверенным всё, что теоретически
управляемо противником, флаг поднимается за пять минут любой работы, становится константой и не
несёт информации — то есть просто сжигает бюджет вопросов.

| Источник | Поднимает | Почему |
|---|---|---|
| Файл проекта | нет | ваш |
| Файл с вашего SSH-хоста | нет | вы завели этот хост и дали учётку. Захваченный хост — инцидент, а не режим работы |
| Значение из вашей SQL-базы | нет | то же |
| Изображение, переданное человеком | нет | ввод пользователя доверен по определению |
| Страница с домена из списка доверенных | нет | оператор назвал домен — это названный остров, как SSH-хост |
| `web_fetch` по ссылке, которую дал человек | **да** | адрес выбрали вы, содержимое пишет владелец сайта. Меняется намерение, а не доверие |
| `web_fetch` / страница в браузере | **да** | адрес никто не называл |
| Вывод чужого MCP-сервера | **да** | чужая голова, чужие правила |
| Грязный блоб или запись KV | **да** | наследование метки |

То есть флаг поднимает ровно одна зона — `Интернет`, остров без имени и без учётки. Строить защиту
от собственной инфраструктуры — паранойя, после которой продуктом перестают пользоваться.

**Список доменов** — тот же механизм именования, что и соединения: домен, внесённый в настройки
(внутренний портал, вики), становится названным островом со своим доверием. Это же даёт правильную
динамику: стал часто ходить — внёс в список — вопросы кончились.

**Сброс флага — человеком и только человеком.** Инструмента для модели нет: флаг, снимаемый тем, от
кого он защищает, бессмыслен. Рядом с кнопкой показывается, что именно его подняло, иначе решение
принимается вслепую. Сброс не отменяет уже отправленного — он влияет только на будущие вопросы,
поэтому цена ошибки ограничена. Внутри чата флаг не сбрасывается ничем автоматическим: ни откатом,
ни чекпойнтом, ни перезагрузкой.

**Видно его в строке состояния** рядом с индикатором подключения: в норме не видно вовсе, при
заражении — заметный красный кружок, а не точка.

**Изображения отдельного правила не требуют.** Картинка наследует зону того, кто её добыл: снимок
экрана от человека доверен, снимок страницы, куда модель сходила сама, равен `web_fetch` той же
страницы.

**Доверие скиллов с флагом не связывается.** Лестница скиллов решает, что позволено скиллу; флаг
решает про выброс наружу. Связав их, мы пометили бы навсегда любой проект, использующий скилл из
репозитория, — ровно тот перегиб, из-за которого модели перестают верить.

**Правило смертельной тройки — единственное, что флаг включает.** Приватные данные плюс содержимое
из неназванного источника плюс канал наружу. Любые два — обычная работа: читали веб и правите файлы
проекта — цена ноль; читали веб и ходите в свою базу — ноль. Все три в одном чате — запись наружу
переспрашивается заново, даже если грант выдан.

Отсюда и цена монотонности: несбрасываемый флаг экономил бы один вопрос в редком сценарии, поэтому
откат его не чистит и это ничего не стоит. И «заражения проекта» не выходит: флаг живёт на чате, в
проект уходит только конкретная запись KV со своим битом — лечится удалением записи.

## 7. Гранты

Единица — ребро, а не вызов. Осмысленных рёбер в живом проекте десятки; после пяти-десяти ответов
проект перестаёт спрашивать. Это и есть критерий качества модели: **не сколько случаев она
различает, а сколько ответов нужно дать, чтобы вопросы кончились.**

Состав записи:

| Поле | Зачем |
|---|---|
| ребро (источник, приёмник, эффект) | что именно разрешено |
| идентификатор острова + отпечаток | чтобы переименование и подмена адреса гасили грант |
| область: чат / проект / машина | чат наследует проект, повышение — явное действие |
| выдан когда | для срока |
| срок | ставится не всем: на `Проект → Контекст` таймаут — издевательство, на запись в остров — разумно |
| применён когда | даёт бесплатный автоотзыв неиспользуемых и чистит карту |

Хранилище — `.spla/grants.yaml`. Не едет в git (вся папка runtime-состояние), не виден агенту (вырез),
привязка к проекту получается без ключевания по идентификатору проекта.

## 8. Где это исполняется

| Что | Где | Состояние |
|---|---|---|
| Вердикт по ребру | `PermissionManager.CheckPermission` | аргументы вызова там уже есть — плумбинг не нужен |
| Классификация зон по пути | новый резолвер поверх `PathBoundary` | четыре нынешние копии сводятся в одну |
| Флаг и метки на ходе к модели | стадия `Policy` конвейера LLM | `LlmPipelineStage.Policy = 100` уже существует и планом конвейера оставлена открытой под будущие хуки |
| Опознание острова провайдера | `LlmTurnContext.ModelId` / `Settings` | известно на входе в конвейер; снизу вверх ничего поднимать не надо |
| Граница файловой системы | `IWorkspace` целиком | **не только `MapPath*`**: десять из двенадцати инструментов зовут `ws.FileExists` / `ws.ReadAllLinesAsync` напрямую |
| Песочница в чате | `ChatRuntime` | сегодня сессия создаётся без неё, всегда `PassthroughSandbox.Default` |

Запрет плагинам вставать на стадии `Accounting` и `Transport` уже реализован, поэтому политику
нельзя обойти сторонним проводом.

## 9. Диалог и карта

Область запоминания живёт внутри кнопки, а не в галочке рядом:

```
[ Разрешить ]  [ Разрешить: Проект → SSH: web-01 ]  [ Отказать ]  [ Отказать и подсказать ]
```

Порядок: разовое — самое частое и безобидное; запоминающее — произносит вслух формулировку гранта,
человек видит её до того, как выдал; отказ; отказ с пояснением, который на практике окажется самым
полезным, потому что им рулят агентом.

`Отказать` и `Отказать и подсказать` различаются не решением, а тем, что получает модель: первое —
политика («так нельзя, ищи другой путь»), второе — ведение («не надо, сделай иначе»). Разница
существенна для продолжения работы, поэтому обе формы доезжают до модели по-разному.

Цвет кодирует необратимость, а не «да/нет»: разовое нейтральное, запоминающее акцентное, отказ
вторичный. Красный на отказе — неверный сигнал: отказ безопасен, опасно согласие.

Чат / проект / машина в четыре кнопки не влезают и не должны: умолчание — проект, остальное меняется
на карте задним числом.

**Карта зон — сами настройки.** Зоны цветом по доверию; рёбра: зелёное разрешено, красное запрещено,
чёрное пунктиром спрашивает, серое — трафика не было; толщина по числу проходов. Клик по ребру
меняет вердикт. Диалог подтверждения — подсветка ребра на той же карте: человек видит не
«browser_upload: allow?», а «файл вне проекта уходит в интернет».

## 10. Чего модель не обещает

Раздел обязательный: без него к затее будут возвращаться каждые полгода с «а вот если…».

- **Мы контролируем именованные каналы, а не все каналы.** Смонтированный сетевой диск, симлинк
  наружу, прокси в переменной окружения — безымянные каналы, они вне модели по построению. Чат,
  перекладывающий файл между папками, может физически отправлять его в интернет, и модель этого не
  увидит.
- **Shell не ограничен зонами.** `system_run_shell` берёт `cwd` от модели и уходит в `LocalShell`
  мимо `Workspace`; `roslyn_script_run` исполняет произвольный C#. Пока `Execute` не изолирован
  средствами ОС, всё остальное — защита от случайности, а не от намерения. Это отдельная работа.
- **Файловая система — прачечная для меток.** Недоверенное содержимое, записанное в файл одним
  чатом и прочитанное другим, теряет метку. Блобы и KV лечатся меткой, файлы — нет.
- **Модель не защищает от человека.** Всё это про агента; человек с тем же продуктом делает что
  хочет.
- **Внедрение в промпт в общем виде не решается, и мы его не решаем.** Заражённый текст может
  прийти из любого источника, включая ваши собственные — файл на вашем сервере, значение в вашей
  базе. Флаг закрывает одну узкую цепочку: «сходил на чужую страницу → тихо выгрузил ваши данные
  наружу». Всё остальное — вне обещаний.
- **Мы не защищаем от вашей собственной захваченной инфраструктуры.** Скомпрометированный SSH-хост
  или база — инцидент, а не режим работы; строить вокруг них периметр значит сделать продукт
  непригодным, ничего не выиграв.

## 11. Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Вложенные уровни доверия без островов | `Проект → SSH` и `SQL: prod → SSH` — оба ребра между доверенными зонами, а смысл противоположный. Уровни этого не выражают, только пары |
| Зона-класс вместо экземпляра (`SQL` вместо `SQL: prod`) | Грант, данный на тестовую базу, молча покрывает боевую. Обещание шире данного — и человек, поняв это однажды, отключает всё |
| Объединить `allow_write` с правилами перемещения | Разная арность: свойство узла против свойства пары. Запись конфигурации на сервер и выгрузка туда зарплат — разные вещи при одном приёмнике |
| Флаг недоверия в контексте | Модель прочитает его как текст, а внедрённая инструкция объявит устаревшим |
| Построчное отслеживание меток через контекст | Ruby выпилил `$SAFE` в 3.0 именно потому, что пообъектный taint неподдерживаем. Метка на блобе и на чате работает, метка на строке — нет |
| Недоверие как свойство содержимого («тут может быть промпт») | Тогда недоверенно всё: файл на вашем сервере, строка из вашей базы. Флаг становится константой и только жжёт бюджет вопросов |
| Уровни доверия вместо одного бита | Порядок между «случайная страница» и «чужой MCP-сервер» назначить честно нельзя; трёхзначная шкала будет применяться наугад |
| Связать лестницу доверия скиллов с флагом чата | Любой проект со скиллом из репозитория оказался бы помечен навсегда. Системы про разное: лестница — что позволено скиллу, флаг — про выброс наружу |
| Особое правило для изображений | Картинка наследует зону добывшего её; снимок экрана от человека — обычный ввод пользователя |
| Грант на инструмент с аргументами | Побайтовое совпадение JSON не повторяется, `*` слишком широк. Отсюда нынешняя усталость |
| Гранты в манифесте проекта | Манифест едет в git — чужое решение приезжает как моё; и агент может его переписать |
| Гранты в `~/.spla` | Рассматривалось и отвергнуто после решения закрыть `.spla/` целиком: раз папка невидима агенту и не в git, оба довода исчезли, а код с ключеванием по проекту сложнее |
| Показывать зоны человеку напрямую | Шесть зон на пять режимов — честная модель, которой никто не пользуется. Наружу остаются четыре категории (`read`/`write`/`shell`/`internet`), зоны выводят их |
| Сразу включить исполнение | Список законных исключений угадать нельзя. Неделя теневого режима заменяет угадывание данными |

## 12. Следствия для существующего кода

**Ломается сразу (решено осознанно):**

- `workspace:` уходит из формата `.spla`. Сейчас поле кладётся в `WorkspacePath` как есть
  (`SettingsResolver.cs:311`) и **никогда не делается абсолютным** — во всех манифестах репозитория
  стоит `workspace: .`, и работает это лишь потому, что на старте делается `chdir`. Комментарий
  `RoslynPlugin.cs:22` о том, что путь абсолютен после резолва, неверен.
- `.spla/` закрывается от агента целиком. Теряется файловый доступ к чатам, секретам, учёту токенов
  и к двум местам, куда доступ был осмысленным: `<workspace>/.spla/logs/` и `.spla/skills`.
- Строка про `<workspace>/.spla/logs/` уходит из `agents/observability.md`. Логи читает человек;
  если агенту однажды понадобится диагностировать свой сбой — это инструмент с хвостом и фильтром,
  а не сырой файловый доступ, потому что многомегабайтный лог в контекст всё равно не читается.
- Источник скиллов `local` (`.spla/skills`) удаляется. Проверено: по доверию он идентичен обычному
  `skills/` — всё внутри рабочей области принудительно понижается до недоверенного
  (`SkillSourceRegistry.cs:419`), — так что покупал он ровно одно: черновик не попадает в коммит.
  Нужен скилл — пусть лежит в проекте.

**Чинится попутно:**

- Относительные пути в сервисе. `Directory.SetCurrentDirectory` делают только CLI и Avalonia
  (`CliBootstrap.cs:45`, `App.axaml.cs:97`); `SPLA.Service` не делает вовсе, а рабочий каталог —
  процессный. При нескольких проектах в одном процессе относительный путь чата резолвится в чужой
  каталог. Корень снимает это без отдельной задачи.
- Серверная изоляция. `LocalProject.GetWorkspace()` отдаёт `new LocalWorkspace()` всем, включая
  сервер (`LocalProject.cs:19`), — то есть «изоляция чисто из корня», как это названо в
  `ServerProjectRoot`, сегодня не работает. Тот же код закрывает и её.
- Четыре реализации проверки «внутри корня» сводятся в одну.

**Всё вышеописанное существует без настоящей песочницы.** `PassthroughSandbox` не принуждает ничего,
и пока `Execute` не изолирован средствами ОС, любая проверка снимается одной командой из шелла.
Это не повод не делать зоны — но повод не называть их защитой и не забыть про
[`PLAN_20260807_host_sandbox`](../plans/PLAN_20260807_host_sandbox.md).

**Локальный и серверный варианты не расходятся.** Зоны — общий словарь, инвентарь зон — свойство
развёртывания: на сервере зоны `Машина` попросту нет, `MapPathToHost` возвращает `null`, и половина
рёбер недостижима не по правилу, а по невыразимости. Задел под виртуальность уже работает —
`IWorkspace` это допускает, и есть тест, доказывающий работу поиска над workspace без диска
(`tests/SPLA.Tests/WorkspaceSearchTests.cs:88`). Не сделан один шаг: подключить виртуальную
реализацию вместо `LocalWorkspace`. Диаметрален ровно один пункт — `Execute`.

## 13. Приложение: каталог сценариев

Записан, чтобы не выводить его заново каждые полгода и чтобы было видно, где мы сознательно
останавливаемся. Безопасность агента — область, где паранойю можно наращивать бесконечно; граница
проводится здесь.

### Защищаемся

| Сценарий | Чем |
|---|---|
| Модель сходила на чужую страницу и собралась выгрузить данные наружу | флаг + правило тройки |
| Скриншот чужой страницы вместо её текста | картинка наследует зону добывшего — тот же флаг |
| Описания инструментов чужого MCP-сервера содержат внедрённый текст | зона сервера; но см. оговорку ниже |
| Отмывание через блоб: налил из недоверенного, отдал в остров | зона происхождения в `BlobEntry` |
| Отмывание через проектный KV: записал в одном чате, прочитал в другом | бит происхождения на записи |
| Переименование соединений местами ради чужих прав | грант ключуется id + отпечатком |
| Подмена адреса или базы у названного соединения | отпечаток гасит грант |
| Смена модели посреди чата как тихая выгрузка накопленного | ребро `Контекст → LLM: <соединение>` |
| Под-агент как выход из периметра | наследование песочницы и флага |
| Откат чекпойнта ради сброса флага | флаг вне отката, снимается только человеком |
| Симлинк или junction наружу из проекта | разбор реальной цели в `PathBoundary` |
| Выход за корень через `..`, UNC, диск | нормализация и отказ в `PathBoundary` |
| Чтение чужих чатов, секретов, грантов проекта | вырез `.spla/` целиком |

Оговорка про MCP: описания инструментов чужого сервера попадают в промпт **до** любого вызова, то
есть флаг поднимается уже после того, как текст прочитан. Это ограничение механизма, а не недосмотр:
единственная полная защита — не подключать сервер, которому не доверяешь.

### Не защищаемся — сознательно

| Сценарий | Почему нет |
|---|---|
| Файл на вашем SSH-хосте содержит внедрённый промпт | ваша инфраструктура. Захваченный сервер — инцидент, а не режим работы |
| Ваша хранимая процедура вернула строку с промптом | то же |
| Текст атакующего в сообщении об ошибке или исключении | это то же содержимое, отдельного правила не заводим |
| Отмывание через файл: чат А записал, чат Б прочитал | метки на файловой системе не держатся; блобы и KV лечатся, файлы нет |
| Смонтированный сетевой диск: перекладывание файла = отправка наружу | безымянный канал, вне модели по построению |
| Прокси или зеркало в переменной окружения | то же |
| Скилл из репозитория проекта с вредным текстом | своя лестница доверия скиллов; с флагом не связываем |
| Человек делает то, чего делать не стоит | модель про агента, не про человека |
| «Гипнотическое» видео или изображение | у модели нет зрительной суггестии; кадр — обычное недоверенное содержимое, ничего сверх |

### Ждёт песочницы

| Сценарий | Состояние |
|---|---|
| `system_run_shell` обходит любые зоны через `cwd` и перенаправление | до изоляции `Execute` все проверки снимаются одной командой |
| `roslyn_script_run` исполняет произвольный C# | то же |
| Git-хук в проекте, срабатывающий на действие агента | исполнение чужого кода, тот же класс |
| Запуск чужого плагина или скилла с кодом | тот же класс |
