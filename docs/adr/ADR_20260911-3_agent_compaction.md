# ADR_20260911-3_agent — сжатие истории: вернуть `/compact`, не стирая историю

Статус: **принято** (2026-09-11), не реализовано. Ветка: `work`.

План работ: [`PLAN_20260911_agent_roles-agents-md-compact`](../plans/PLAN_20260911_agent_roles-agents-md-compact.md).

Смежное: [`ADR_20260911-2_agent_agents-md-scopes`](ADR_20260911-2_agent_agents-md-scopes.md)
(пометки областей AGENTS.md — сжатие обязано их не трогать),
[`ADR_20260910-2_agent_chat-feed`](ADR_20260910-2_agent_chat-feed.md) (как чат отдаёт снимок окну).

---

## 1. Что случилось

Сжатие было с самого начала — `/compact` в Avalonia (`ChatSessionViewModel.CompactContextAsync`).
Оно удалено вместе со всем нативным интерфейсом в `b4ba2d5` («Stage C: delete dead native UI»,
2026-06-26) и не перенесено ни в сервис, ни в web, ни в CLI. Осталась осиротевшая настройка
`agent.compact_tail_messages` (по умолчанию 2): читается каскадом, не используется ничем.

Как оно было устроено:

1. резервная копия чата (`SaveBackup(..., "before_compact")`);
2. в модель без инструментов уходят только реплики человека и ассистента и промпт «Compress the
   conversation into a working summary… facts, decisions, constraints, open questions, modified
   files, commands, and the next step… Respond in Markdown»;
3. история очищается целиком; добавляются пересказ как `System`-сообщение и последние
   `CompactTailMessages` реплик.

Три слабых места старой схемы в нынешнем коде:

- очистка стирает историю, которую человек потом хочет прочитать — отсюда и резервная копия;
- `System` в середине истории ломает шаблоны многих локальных моделей и **не сохраняется в YAML**
  (`Conversation.ShouldPersist` отбрасывает `ChatRole.System`) — после переоткрытия чата пересказ
  исчез бы;
- после сжатия модель не знает, что уже пробовала и что не вышло, и ходит по кругу.

## 2. Решение

### 2.1. Не стирать, а скрывать: `ContextRetention.Never`

Механизм уже есть: `ContextAssembler.Assemble` отбрасывает сообщения с
`RetentionPolicy = Never`. Сжатие:

1. отказывает посреди хода (как ответвление — «полусобранную историю никому не отдаём»);
2. выбирает хвост: последние `compact_tail_messages` реплик человека, граница хвоста — всегда перед
   репликой человека, чтобы не разрезать пару «ассистент с `tool_calls` → результаты»;
3. отправляет в модель без инструментов то, что модель видит сейчас (`Assemble`) до хвоста, **без
   пометок областей и без меток**, с промптом сжатия (§2.4);
4. всем сжатым сообщениям ставит `RetentionPolicy = Never` и `CompactedBy = <MsgId пересказа>`;
5. вставляет пересказ **перед хвостом** отдельной записью (§2.2).

Сжатые сообщения остаются в истории и в YAML: человек их видит (приглушёнными), модель — нет.
Резервная копия больше не нужна.

Это первый в коде, кто присваивает `RetentionPolicy`. Ловушка, описанная в
[`PLAN_20260827_core_context-retention`](../plans/PLAN_20260827_core_context-retention.md) §2 —
`Never` на результате инструмента без его вызова рвёт пару и провайдер отвергает запрос, — здесь не
срабатывает: скрывается весь префикс целиком, а граница хвоста всегда перед репликой человека, так
что ни одна пара «вызов → результат» не оказывается по разные стороны. Тот план (вытеснение
отдельных результатов) этим решением не закрывается и остаётся открытым.

`RetentionPolicy` сейчас в YAML, по всей видимости, не сохраняется (`ChatSessionMessage` не имеет
такого поля) — сохранение этого поля и `CompactedBy` входит в работу. Иначе после переоткрытия чата
модель снова увидела бы всё.

### 2.2. Пересказ — запись с ролью `User` и признаком

| Поле `ChatMessage` | Значение |
|---|---|
| `Role` | `User` — не `System`: шаблоны локальных моделей и `ShouldPersist` |
| `Content` | `--- Compacted context (summary) ---\n` + текст пересказа |
| `CompactSummary` | `true` — новый флаг: интерфейс рисует плашкой «сжатый контекст», а не репликой человека |
| `MsgId` | `C-<n>` — новый префикс |

### 2.3. Пометки областей AGENTS.md не трогаются

Пометки (`ScopeMarker`, ADR_20260911-2 §2.5) в модель не уходят, поэтому:

- не идут на вход сжатия;
- не получают `Never`;
- остаются на своих местах и продолжают работать — правила областей переживают сжатие без переноса.

То же для меток (`IsLabel`): их не видит модель, сжатию до них нет дела.

### 2.4. Промпт сжатия

Английский (правило 8 `agents/sys_prompt_rules.md`), при реализации сверяется с этим файлом:

```text
Summarize the conversation so far into a working state that lets the work continue without it.

Keep:
- the goal and what the user asked for, in their terms;
- decisions made and why, and constraints that were stated;
- files created or changed, with paths, and what changed in each;
- commands or tool calls whose results still matter, with the result in one line;
- what was tried and failed, so it is not tried again;
- open questions and the next step.

Drop: greetings, restated rules, tool output that was only read once, and reasoning that led nowhere.
Do not restate project instructions; they are kept separately.
Write in the language the user writes in. Use short Markdown sections.
```

Отличия от старого: «что пробовали и не вышло» (без него модель после сжатия ходит по кругу), пути с
сутью изменений, запрет пересказывать правила (они живут отдельно — корень в промпте, области по
пометкам).

### 2.5. Откат через границу сжатия

Откат к якорю, стоящему до пересказа, отрезает пересказ, а флаги `Never` на сообщениях между якорем и
пересказом остались бы — история вышла бы дырявой.

Правило: **обрезка, убравшая пересказ, снимает `Never` со всех сообщений с его `CompactedBy`.** Откат
возвращает ровно то, что было до сжатия. Это делает `Conversation.TruncateTo`, а не каждый вид отката
по отдельности — у отметок, контрольных точек, `chat.rewind` и ответвления одна обрезка.

Повторное сжатие поверх сжатого: прежний пересказ сжимается как обычное сообщение (получает `Never` и
новый `CompactedBy`). Откат, отрезавший новый пересказ, снимает только его `Never` — старый пересказ
снова виден, всё до него остаётся скрытым первым сжатием.

### 2.6. Где запускается — одна операция, три входа

- серверная операция `chat.compact { chatId }` → ответ свежим снимком чата (как `chat.rewind`);
  новое сообщение протокола — по `agents/protocol.md`;
- `/compact` в поле ввода web-чата — перехватывается клиентом, в модель как текст не уходит;
- `/compact` в REPL CLI и `spla chat compact <id>` для пакетного режима (живой экземпляр — через
  провод, как `RemoteChatRun`).

Сжатие только по команде человека. Автоматическое сжатие по заполненности контекста — отдельное
решение, не здесь (есть `IContextBudgetHost`, есть подсказка «compact the conversation» в
`ResultBudgetStage`).

## 3. Рассмотренные варианты

- **Очистка, как было.** Отклонено: стирает историю для человека, требует резервной копии, пересказ
  `System` не переживает сохранение.
- **Пересказ `System`-сообщением.** Отклонено: шаблоны локальных моделей, `ShouldPersist`.
- **Перенос пометок областей в пересказ текстом.** Отклонено: пометки не видны модели и не
  нуждаются в переносе — они остаются на месте.
- **Отдельный «сжатый» файл чата рядом с полным.** Отклонено: две истории одного чата, которые
  рано или поздно разойдутся; `Never` даёт то же в одной.

## 4. Следствия

- `compact_tail_messages` снова что-то значит.
- Сжатие ломает кэш префикса — неизбежно и приемлемо: оно редкое и по команде.
- Интерфейсу нужно различать сжатые сообщения (приглушить) и пересказ (плашка) — два признака в
  DTO сообщения, по `agents/protocol.md`.
