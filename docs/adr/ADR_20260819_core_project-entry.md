# ADR_20260819_core — вход в проект: профили запуска и папка без манифеста

Статус: **принято**

Опирается на [`ADR_20260811_core_security-zones`](ADR_20260811_core_security-zones.md) (корень = каталог
манифеста) и [`ADR_20260814_core_project-mounts`](ADR_20260814_core_project-mounts.md) (граница —
объект проекта).

> В контексте **запуска SPLA в произвольной папке, у которой нет манифеста**, столкнувшись с тем, что
> **его отсутствие молча выдаёт максимальные права, чужие настройки и общее состояние в `~/.spla`**, мы
> решили **не наследовать окружение молча: профиль запуска задаётся параметром CLI и работает как
> шаблон, применяемый один раз при создании манифеста**, чтобы **папка получала ровно те права,
> которые ей выдали явно**, приняв **отказ от поиска манифеста вверх по дереву и падение вместо
> вопроса в неинтерактивном режиме**.

---

## 1. Контекст

Разбор начался с бытового: чтобы внешний агент (Claude Code) мог пользоваться SPLA в чужой папке,
там нужен `*.spla`. Предполагалось, что без него SPLA работает «ограниченно». Код говорит обратное.

**Без манифеста прав больше, а не меньше.** `HasProject == false` даёт
`PathBoundary.None` (`LocalProject.cs:28`) и `PassthroughSandbox.Default` (`AgentRuntime.cs:428`), а
`EdgeLedger` не пишется вовсе (`AgentRuntime.cs:263`). То есть безпроектный режим — это режим без
корня, без вырезов и без учёта рёбер.

**Состояние утекает в общую папку.** `LocalProjectBackend.For` (`LocalProjectBackend.cs:31`) при
отсутствии манифеста делает рабочим каталогом `~/.spla/`. Чаты, KV, логи и `token-usage.json` любой
безпроектной сессии складываются туда вперемешку с чужими.

**Настройки берутся целиком из `defaults.yaml`** — коннекты, `agent.capabilities`, плагины, режим. Это
и есть «в общем что-то настроено, а нам не надо», только шире: наследуется не часть, а всё.

**Провалиться в этот режим легко случайно.** `ConfigLoader.FindProjectFile` (`ConfigLoader.cs:342`)
смотрит только в саму папку и при нескольких `*.spla` берёт `files[0]` без сортировки. Запуск из
подпапки проекта — уже безпроектный запуск.

---

## 2. Принятые решения

| Решение | Обоснование |
|---|---|
| Профиль запуска — **параметр CLI**, а не поле в `*.spla` | Профиль отвечает на вопрос «как заводим», а не «что это за проект»; в манифесте ему нечего делать после создания |
| Профиль применяется **один раз, при создании** манифеста, и пишет в него явные `agent.capabilities` | Поле с рантайм-смыслом стало бы вторым источником истины рядом с `agent.capabilities`, и сразу появился бы вопрос «кто кого перебивает» |
| Существующие манифесты **не меняют смысла**: нет профиля — нет и вопроса | Иначе трактовка «нет профиля ⇒ minimal» молча отобрала бы инструменты у всего, что уже работает, включая `spla.spla` этого репозитория |
| Профили: `standard` (всё встроенное + плагины/скиллы машинного слоя), `minimal` (пусто, даже `core.*`), `inherit` (сегодняшнее поведение) | Три различимых намерения; больше градаций не нужно, они выражаются правкой `agent.capabilities` |
| Дефолт — **`minimal`** | Остальное выдаёт права, которых не ждали; для `chat run` минимума часто достаточно |
| LLM-коннект наследуется даже в `minimal` | Коннект — не capability; без него команда не поедет вообще, и запрет ничего не защищает |
| **Поиска манифеста вверх по дереву нет** | Запуск действует ровно там, где стоишь. Неявный подъём — это молчаливый выбор чужого корня за пользователя |
| Папка без манифеста: UI спрашивает, CLI требует явного `--init[=профиль]` | Тихое наследование `defaults.yaml` со снятой границей перестаёт быть поведением по умолчанию |
| Неинтерактивный `chat run` без манифеста **падает** с внятным сообщением | Скрипт не может ответить на вопрос; молчаливое создание манифеста в чужой папке — тоже не ответ |
| `inherit` остаётся достижимым, но только явным опт-ином | Режим полезен для одноразового прогона; вредна была его роль умолчания |

---

## 3. Отвергнуто

**Профиль как поле манифеста с рантайм-смыслом.** Даёт второй источник истины рядом с
`agent.capabilities` и ломает трактовку существующих файлов.

**Всегда автоматически создавать манифест.** Предсказуемо, но засоряет чужие каталоги `.spla`-файлами
там, где человек просто зашёл посмотреть.

**Поиск манифеста вверх по дереву.** Убирает один класс случайностей и вводит другой, хуже: команда,
запущенная в подпапке, начинает действовать в корне, о котором её не спрашивали.

---

## 4. Последствия

- `ConfigLoader.FindProjectFile` остаётся односложным (только текущая папка), но недетерминированный
  выбор `files[0]` при нескольких манифестах должен стать явной ошибкой, а не жребием.
- Появляется команда создания проекта с профилем и **одна доменная фабрика**, которую зовут CLI,
  Avalonia и сервис. Сегодня логика размазана по `LocalProjectProvider.Create`,
  `ConfigLoader.ScaffoldIfNew`, `MainWindow.NewProjectAsync` и `ProjectHandlers.Create`.
- Диалог «Новый проект» получает папку, имя (по умолчанию из папки), профиль и строку предпросмотра
  «будет создан `…\Demo.spla`». Сейчас Avalonia не даёт задать имя вообще.
