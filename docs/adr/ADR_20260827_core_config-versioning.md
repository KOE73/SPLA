# ADR_20260827_core — версии хранимых файлов и миграторы

Статус: **принято**

Опирается на [`ADR_20260819-2_core_agent-instances`](ADR_20260819-2_core_agent-instances.md)
(терпимость кадров реестра к чужому поколению) и
[`ADR_20260731_docs_genres-and-naming`](ADR_20260731_docs_genres-and-naming.md).

> В контексте **смены формата файлов, которые уже лежат у людей после релизных zip**, столкнувшись
> с тем, что **поле `version` пишется во все файлы, но не читается ни одним загрузчиком**, мы решили
> **разделить номер и миграторы: номер начинает работать сразу — отказом читать файл из будущего, —
> а цепочка миграторов пишется только к первому реальному слому**, чтобы **откат на предыдущий релиз
> не терял данные молча**, приняв **явный отказ загрузки вместо частичного чтения**.

---

## 1. Контекст

**Номер версии уже есть и уже бесполезен.** `version` объявлен в `SplaProject.cs:11`,
`SplaDefaults.cs:10` и `ChatSession.cs:8`, со значением по умолчанию `1`, и лежит первой строкой в
`spla.spla`. При этом ни `ConfigLoader`, ни `ChatManager` не содержат ни одной проверки `.Version`.
Поле — украшение: оно пишется, читается в модель и никогда ни на что не влияет.

**Молчаливая потеря данных достижима уже сегодня.** Приложение публикуется релизными архивами
(`SPLA.zip`, `v0.<minor>.<build>`), то есть откат на предыдущую сборку — обычное действие, а не
экзотика. Последовательность: человек обновился, поработал, формат чата обогатился полем; человек
откатился; старая сборка читает новый файл, YAML отбрасывает незнакомые узлы, следующее сохранение
пишет обеднённый файл обратно. Ни ошибки, ни предупреждения — данные просто исчезают.

**Хранимое и живое путают, а лечатся они противоположно.** Старый *файл* встречает новый код —
стороны не одновременны, файл мёртв, его можно поднять до текущей версии: это **миграция**. Хаб
одного поколения встречает участника другого — стороны живы одновременно, переписать собеседника
нельзя: это **терпимость**. Вторую задачу проект уже решил осознанно (`RegistryProtocol`: тип плюс
непрозрачное тело, значения строками, а не enum, «чтобы не превратить незнакомое в ошибку
парсинга»). Не решена именно первая, более простая.

---

## 2. Принятые решения

| Решение | Обоснование |
|---|---|
| **Номер и миграторы разделяются.** Номер начинает работать немедленно; миграторы пишутся к первому слому формата | Дорогая часть (цепочка) откладывается законно, дешёвая (сравнение числа) перестаёт быть украшением сразу |
| **Версия больше известной — отказ с внятным сообщением**, а не частичное чтение | Единственная защита от потери данных при откате на предыдущий релиз; ради неё и вводится вся дисциплина |
| Версия меньше известной — прогон через цепочку миграторов (пока пустую) | Место для будущего кода объявлено заранее, чтобы первый слом не требовал перестройки загрузчика |
| Отсутствие `version` — считать первой версией | Файлы, созданные до дисциплины, читаются без спецслучая |
| **Мигратор работает с сырым узлом документа**, а не с типизированной моделью | Типизированный `v1 → v2` ломается, как только модель уедет вперёд: мигратор в прошлое обязан не зависеть от настоящего |
| **Опубликованный мигратор не правят никогда**; ошибка исправляется следующим в цепочке | Иначе у двух людей с одним номером версии оказываются разные данные |
| Миграция **ленивая**: подъём при чтении, запись при следующем сохранении | Массовая конвертация папки непременно упадёт на середине, и это худшее из состояний |
| Тесты миграторов идут от **живого файла старой версии**, а не от сгенерированного текущим кодом | Иначе тест проверяет лишь, что код согласен сам с собой |
| `version` добавляется в новые хранилища (`grants.yaml`, `project-kv.yaml`) при их появлении | Дописать номер в момент создания стоит одну строку, а задним числом — уже миграцию |

## 3. Отвергнуто

**Мигрировать всё сразу при обновлении.** Массовый проход по папке чатов — длинная операция без
транзакции; падение на середине оставляет половину файлов поднятыми, половину нет, и номер версии
перестаёт что-либо значить.

**Ограничиться собой и не выводить дисциплину в релизы.** Отложить можно миграторы, но не отказ
читать файл из будущего: он защищает именно чужие данные, а стоит десяток строк на загрузке.

**Типизированные миграторы через модели.** Читаются приятнее, живут до первого переименования
свойства — после чего мигратор древней версии начинает зависеть от формы, которой в его эпоху не
существовало.

**Считать отсутствие `version` ошибкой.** Отбросило бы все файлы, созданные до этого решения, ради
случая, который однозначно трактуется соглашением.

---

## 4. Последствия

- `ConfigLoader` и `ChatManager` получают общую проверку версии на входе; сегодня она умеет ровно два
  ответа — «читаю» и «файл новее, чем понимает эта сборка».
- Цепочка миграторов вводится пустой. Первый её участник появляется вместе с первым сломом формата.
- Первым сломом ожидается ролевое поле сессии (`as:`) — мелкое, безопасное и потому удобное, чтобы
  обкатать схему до того, как она понадобится на чём-то дорогом.
- Поле `role` внутри сообщений чата не переименовывается: это зеркало протокола провайдера, и его
  переименование заставило бы файл истории врать о собственном содержимом.
