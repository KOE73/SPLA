# Локализация интерфейса

Интерфейс переводится **одним словарём на всё окно**. Ключ — сам английский исходный текст, а не
выдуманный идентификатор вида `settings.mcp.title`.

Из этого следуют три свойства, за которые не пришлось ничего платить:

* **Непереведённое остаётся английским.** Отсутствующий ключ рендерится как есть, а не как отладочный
  мусор на экране, — поэтому словарь можно доливать панель за панелью.
* **Строки с сервера и из плагинов переводятся бесплатно.** Заголовок схемы, имя возможности, текст
  ошибки — всё, что проходит через `t()` в точке отрисовки, ищется в том же словаре. На бэкенде для
  этого не потребовалось ни одной правки.
* **Никакого этапа придумывания ключей.** Правка шаблона механическая: `>Cancel<` → `{{ t('Cancel') }}`.

## Где что лежит

| Файл | Что это |
|---|---|
| `web/src/i18n/index.ts` | `t()`, реактивный `locale`, список языков, мост к оболочке Avalonia |
| `web/src/i18n/ru.json` | словарь: английский исходник → русский перевод |
| `web/scripts/i18n-scan.mjs` | `npm run i18n:scan` — что в словаре отсутствует, а что в нём лишнее |
| `src/plugins/*/[wW]eb/src/i18n.ts` | переводчик, одолженный плагину хостом (своего словаря у плагина нет) |
| `src/apps/SPLA.UI.Avalonia/Helpers/Localization.cs` | тултипы нативной рамки окна |

Язык выбирается в **Настройки → Оформление → Язык**. Это преференс устройства: он лежит в
`localStorage`, в `.spla` не попадает — два человека в одном проекте читают интерфейс каждый на своём
языке. Переключение применяется мгновенно, без перезагрузки.

## Как добавить строку

1. В шаблоне: `{{ t('Add host') }}`, в атрибуте: `:placeholder="t('folder path')"`.
2. Для подстановки — именованные плейсхолдеры: `t('{active} of {total} named', { active, total })`.
   Подстановка происходит **после** поиска в словаре, поэтому переводчик волен менять их порядок.
3. `npm run i18n:scan` покажет строку в списке отсутствующих. Добавьте пару в `ru.json`.

Термины берутся из `agents/glossary.md` — там записано, почему выбрано именно это слово.

### Абзац с разметкой внутри

Предложение, внутри которого есть `<code>` или `<b>`, переводится **целиком**, а не кусками:
дробление лишает переводчика возможности переставить части.

```html
<p class="hint" v-html="t('Takes effect on the next <code>spla serve</code> start.')"></p>
```

Две тонкости этого приёма:

* Значение атрибута один раз проходит HTML-декодирование, прежде чем попасть в `t()`. Поэтому
  сущность, которая должна **показаться** как текст, пишется удвоенной: `&amp;lt;port&amp;gt;` —
  тогда до `v-html` доедет `&lt;port&gt;`, и человек увидит `<port>`. Ключ в словаре при этом
  содержит `&lt;port&gt;`, а не `<port>`.
* Двойная кавычка внутри атрибута пишется как `&quot;` — а ключ в словаре содержит обычную `"`.

`i18n-scan` декодирует ключи из атрибутов так же, как это делает браузер, поэтому его отчёт совпадает
с тем, что происходит в рантайме.

### Строка, которую собирают в скрипте

Держите в переменной **английский** оригинал, а переводите в момент отрисовки — тогда переключение
языка перерисует и её:

```ts
hint.value = p.canPersist === false ? "no .spla project — session-only" : "";
```
```html
<span class="hint">{{ t(hint) }}</span>
```

## Плагины

Плагинный бандл собирается отдельно от хоста и словаря не везёт. Хост передаёт ему свою функцию `t`
через контракт `mount()` (`PluginSettingsMountApi`), а `src/i18n.ts` внутри плагина её запоминает.
Строки плагина при этом попадают в общий `ru.json` — ключ-то английский. Старый хост, который `t` не
передал, ничего не ломает: панель просто остаётся английской.

## Нативная рамка

Оболочка Avalonia — это несколько кнопок с тултипами. `Localization.cs` обходит дерево и подменяет
тултипы, запоминая исходный английский в побочной таблице (иначе второй проход искал бы уже русскую
строку). Язык туда приходит по мосту webview сообщением `{ kind: "lang", lang }` — своей настройки
языка у рамки нет и быть не должно: человек выбирает язык один раз, внутри окна.

## Что переводить не надо

Промпты и описания инструментов, содержимое чата, код, вывод терминала, пути. Первое адресовано
модели, остальное принадлежит человеку — ни то, ни другое не UI.

Технические токены (`stdio`, `npx`, `postgres`, образцы вроде `sql01 or 192.168.1.10`) в словарь не
кладутся сознательно: `i18n-scan` показывает их как отсутствующие, и это нормальное состояние.
