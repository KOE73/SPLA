# Промпт: миграция SPLA-конфигов на дерево соединений

Скопируй всё, что ниже разделителя, в агента, работающего в целевом репозитории.
Обратная совместимость не поддерживается: старые ключи не читаются, файл со старой схемой
загрузится молча-неправильно или не загрузится вовсе.

---

Ты мигрируешь конфигурацию SPLA на новую схему соединений. Работай по шагам, ничего не пропуская.

## Что изменилось

Раньше запись в `connections:` была плоской: один провайдер + один эндпойнт + одна модель + ключ.
Теперь это **дерево из двух уровней**:

- **соединение** — учётка провайдера: `provider`, `endpoint`, `api_key`, новый необязательный
  `admin_key`, `swap_model`. Всё, что является свойством ключа, а не модели.
- **модель** (`models:`) — лист, на который ссылается чат: `id`, `name`, `model`, `context_length`.

Причина: ключ и эндпойнт общие для всех моделей, доступных через них. В плоской схеме три модели
OpenRouter означали три копии ключа.

## Шаг 1. Найди файлы

```
*.spla                       — проектные конфиги
.spla/chats/*.yaml           — файлы чатов
~/.spla/defaults.yaml        — машинные умолчания, если есть
```

Пропускай копии в `bin/`, `obj/`, `dist/`, `node_modules/` — они пересоздаются сборкой.

## Шаг 2. Реши, нужна ли конвертация

**Если в файле нет ключа `connections:` — не трогай его.** Секция `llm:` (`provider`/`endpoint`/
`api_key`/`model`) по-прежнему поддерживается: из неё синтезируется одно соединение с одной моделью,
у обоих `id: default`. Такие проекты работают без правок.

Конвертировать нужно только файлы с явным блоком `connections:`.

## Шаг 3. Преобразуй каждую запись `connections:`

| Старое поле | Куда |
|---|---|
| `id`, `name`, `provider`, `endpoint`, `api_key`, `swap_model` | остаются на **соединении** |
| `model` | уезжает в `models[0].model` |
| `context_length` | уезжает в `models[0].context_length` |
| `lock_model` | **удалить** — поля больше нет |

Каждая старая запись даёт одно соединение с **ровно одной** моделью внутри.

Было:

```yaml
connections:
- id: default
  name: Default
  provider: lmstudio
  endpoint: http://127.0.0.1:1234/v1/
  api_key: lm-studio
  model: google/gemma-4-12b-qat
  lock_model: false
  swap_model: false
```

Стало:

```yaml
connections:
- id: default
  name: Default
  provider: lmstudio
  endpoint: http://127.0.0.1:1234/v1/
  api_key: lm-studio
  swap_model: false
  models:
  - id: default-gemma-4-12b-qat
    name: Gemma 4 12B QAT
    model: google/gemma-4-12b-qat
```

### Как назначать `id` модели

`id` модели **уникален глобально по проекту** — чат ссылается на него плоско, без имени соединения.
Дубликат бросает исключение при загрузке и отклоняется при сохранении.

Схема имени: `<id соединения>-<slug модели>`. Slug — нижний регистр, всё кроме `[a-z0-9]` в дефис,
дефисы по краям убрать. Если `model` пустой или `auto`, бери `<id соединения>-auto`.

`name` — человекочитаемый ярлык; если осмысленного нет, опусти, подставится строка модели.

### Провайдер

Если `provider: openai-compat`, а `endpoint` указывает на `openrouter.ai` — поменяй на
`provider: openrouter`. Это отдельный провайдер: он шлёт `usage.include`, чтобы стоимость приходила
фактом от провайдера, а не пересчитывалась нами.

Известные id: `lmstudio`, `vllm`, `openai`, `openrouter`, `openai-compat`. Незнакомый id теперь
**падает** с ошибкой, а не отрабатывает молча на дефолтном клиенте.

## Шаг 4. Файлы чатов

В `.spla/chats/*.yaml` переименуй ключ:

```
connection_id:  →  model_id:
```

**Значение тоже меняется** — оно теперь указывает на лист:

- проект был на `llm:` без `connections:` → значение остаётся `default`, меняется только ключ;
- проект имел `connections:` → подставь новый `id` модели, который ты назначил на шаге 3.

Не делай это глобальным `sed` по всем репозиториям сразу: соответствие своё в каждом проекте.

Обрати внимание: старый ключ **не вызывает ошибку**. Десериализатор чатов игнорирует незнакомые
поля, так что забытый файл прочитается с пустым `model_id`, и чат тихо свалится на первую модель в
списке. Проверяй результат подсчётом, а не на глаз:

```bash
grep -rc '^connection_id:' --include=*.yaml .    # должно быть пусто
```

Если приложение запущено, оно может переписать открытый чат уже после твоей правки — прогони
проверку ещё раз в конце.

## Шаг 5. Секреты

Если `api_key` записан открытым текстом — это находка, а не деталь. Скажи об этом явно, замени
значение на ссылку `secret:<имя>` и предупреди, что ключ надо **отозвать и перевыпустить**: он уже
мог попасть в git-историю. Не переноси открытый ключ в новый файл как есть.

## Шаг 6. Проверь

Загрузи каждый изменённый `.spla` и убедись, что число моделей совпадает с ожидаемым, а `provider` и
`model` у каждой — те, что задумывались. Пустой `models:` у соединения — легально (наполовину
настроенное), но в пикере оно не появится; если ожидал модель, значит конвертация потерялась.

Отчитайся таблицей: файл → сколько соединений → сколько моделей → что поменял. Отдельной строкой —
всё, что нашёл по секретам.
