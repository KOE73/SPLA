# PLAN_20260828_diagrams — Редактор схем v2

Статус: **к исполнению**. Кода нет.

Решение и обоснование: [`ADR_20260828_diagrams_model-contract-v2`](../adr/ADR_20260828_diagrams_model-contract-v2.md).
Формы файлов: [`docs/diagrams/projects/AGENTS.md`](../diagrams/projects/AGENTS.md).
Парная работа по утилите: [`tools/spla-atlas/AGENTS.md`](../../tools/spla-atlas/AGENTS.md).

**Пишется новый пакет `tools/spla-atlas-editor`, а не правится существующий.**
`tools/spla-diagram` остаётся работающим на контракте v1 до конца переезда и
служит референсом — ровно так же, как `tools/spla-arch` для утилиты.

---

## 1. Почему это главное

Утилита — обслуга: ведёт реестр и больше ничего. **Схему собирает человек здесь.**
После перехода на v2 вид перестаёт появляться сам: сущность попадает на холст
только вытаскиванием из базы. Значит без панели базы v2 не просто неудобен — им
нельзя пользоваться вообще.

---

## 2. Что берётся из v1 и что пишется заново

Честная граница. «С нуля» не означает «переписать пять с половиной тысяч строк»:
часть слоёв про контракт не знает вовсе и переносится почти дословно, а часть
завязана на v1 насквозь и подлежит написанию заново.

### Переносится почти дословно (контракт-агностично)

| Что | Где в v1 | Замечание |
|---|---|---|
| геометрия | `src/geometry/` | чистая математика |
| вьюпорт, пан/зум | `src/canvas/Viewport.ts` | |
| SVG-хелперы, defs | `src/canvas/svg.ts`, `defs.ts` | |
| маршрутизация рёбер | `src/canvas/routing/`, `ports/` | недавно чинилось, работает |
| рендеры элементов | `src/canvas/render/` | кроме нового профиля `detail` |
| библиотека стилей | `src/model/StyleLibrary.ts`, `style-*.ts` | `styles.json` контракт не меняет |
| история | `src/editor/History.ts` | |
| экспорт в drawio | `src/editor/io/drawio.ts` | станет первым экспортёром реестра |

Переносить **осознанно**: прочитать, понять, перенести. Не копировать вслепую —
часть комментариев описывает решения контракта v1, которых больше нет.

### Пишется заново

| Что | Почему |
|---|---|
| модель и IO | контракт другой: реестры + вид вместо одного файла; принадлежность явная |
| дерево документа | v1 строит его выведением из геометрии, v2 читает явные поля |
| панели (инспектор, база, стили) | появляется третья, меняется содержимое двух |
| видимость связей | поимённая вместо глобальной по семейству |
| сохранение | раздельное по файлам вместо одного документа |
| темы | четыре из основного проекта вместо одной жёстко тёмной |

### Не переносится вообще

| Что | Почему |
|---|---|
| `hiddenEdgeFamilies` / `setEdgeFamilyHidden` | глобальная политика по семейству, отменена ADR §4 |
| `linkZoneHierarchy`, `innermostContaining` | геометрическое выведение вложенности; в v2 принадлежность явная (ADR C-2) |
| миграция inline-цветов зон (`migrateInlineZoneStyle`) | одноразовая история v1; в v2 приходят уже с `styleId` |
| обработка зоны `НЕ РАЗМЕЩЕНО` | зоны не существует (ADR C-11) |

## 3. Потоки работ

### Поток A — темы

В v1 десять токенов в `:root` и **82 захардкоженных hex** мимо них, палитра жёстко
тёмная. В основном проекте
[`web/src/styles/themes.css`](../../web/src/styles/themes.css) уже есть **ровно
четыре** темы: `dark`, `emerald`, `cream`, `light`, и словарь токенов почти
совпадает:

| v1 редактора | проект |
|---|---|
| `--bg`, `--panel`, `--text`, `--muted`, `--accent`, `--accent-soft`, `--danger` | те же имена |
| `--panel-alt` | `--elevated` |
| `--line` | `--border` |

1. Взять четыре темы как есть, селекторами `:root[data-theme="…"]`.
2. Словарь проекта богаче (`--faint`, `--ok`, `--warn`, `--code-bg`) — использовать
   его, а не сплющивать всё в `--muted`.
3. Переключатель в шапке, выбор в `localStorage`.
4. **Умолчание — `cream`.**
5. Цвета холста — из того же словаря, чтобы «схема светлая» и «интерфейс светлый»
   перестали быть двумя настройками.

Готово, когда: ни одного hex-литерала вне блоков определения тем.

### Поток B — модель и чтение v2

Сердце пакета. Один модуль знает формат файлов, всё остальное работает с деревом
в памяти — это разделение в v1 себя оправдало и сохраняется.

- реестры читаются вместе: `project.json` → `entities`, `relations`,
  `containers`, `text.<lang>`, затем один вид;
- **принадлежность берётся из явных полей** (`placements[].zone`,
  `zones[].parent`), геометрия ни на что не влияет;
- `zone: null` — законное состояние: элемент в пустом поле вне контейнеров;
- тексты с фолбэком на базовый язык; отсутствующий ключ — не ошибка;
- имя сущности не переводится никогда;
- счётчика в имени зоны нет — число считает рендер по содержимому вида;
- v1 **не читается**: конверсия — дело `spla-atlas convert`, а не редактора.

Готово, когда: проект открывается, закрывается и открывается снова без диффа.

### Поток C — холст

Перенос слоёв из §2 плюс отличия:

- метка «N скрытых связей» в углу узла;
- отдельный слой призраков поверх рёбер;
- профиль рендера читается из размещения.

### Поток D — видимость связей

Три вещи, ни одной глобальной политики:

1. **Метка на узле** — число скрытых связей этого элемента. Ноль взаимодействий,
   видно при взгляде на схему. Отвечает на «как я узнаю, что они есть».
2. **Призраки.** Клик по метке — все связи узла рисуются приглушённо, включая
   скрытые; клик по призраку переключает. Повторный клик по метке гасит.
   **Метка и есть кнопка**: ни тумблера на панели, ни выдержки мышью — схема не
   должна шевелиться сама, пока человек просто ведёт мышь.
3. **Список в инспекторе** — тип, подпись, второй конец, галочка. Рабочая лошадка:
   призраки для ориентации, разбор двух десятков связей делается списком.

Массовые операции: выделить по типу, по зоне, по одному концу — переключить
пачкой. Записывается всё равно поимённо, в `relations.default` / `except` вида.

Правило обоих концов действует всегда и ничего не хранит: связь видна, только
если на виде есть обе её сущности.

### Поток E — панель базы

Третья вкладка рядом со «Свойствами» и «Стилями». Содержимое — `entities.json`:

- поиск по имени и по `codeRef`;
- группировка переключателем: по контейнеру (с учётом `overrides`) или по пути в
  коде;
- пометка «уже на этом виде / нет»;
- `status: gone` — отдельным разделом внизу, это очередь разбора;
- вытаскивание на холст перетаскиванием или двойным кликом. Контейнер из реестра —
  **подсказка** для начальной зоны, не предписание: положить можно куда угодно,
  в том числе в пустое поле.

Туда же вытаскивание контейнеров (как новой зоны вида) и связей.

Готово, когда: пустой вид набирается с нуля, не открывая JSON.

### Поток F — раздельное сохранение

| Пишется | Что |
|---|---|
| `views/<id>.view.json` | геометрия, принадлежность, `styleId`, `render`, видимость связей |
| `text.<lang>.json` | описания, имена контейнеров и видов, подписи связей |
| `relations.json` | связи, добавленные мышью, с `origin: "manual"` |
| `containers.json` | контейнеры и `overrides` |
| `entities.json` | **никогда**, кроме переименования сущности |

Переименование (правка `name` при неизменном `id`) — **явное действие с
подтверждением**, а не побочный эффект правки поля.

**Резервная копия перед перезаписью вида** — снимок в `.spla/diagram-backups/` с
меткой времени. Разделение файлов защищает от машины; от «сохранил поверх»
защищает только это, и стоит оно десяти строк.

Готово, когда: правка описания трогает только `text.*.json`, сдвиг бокса — только
`*.view.json`, и ни одно действие не трогает `entities.json`.

### Поток G — профиль `detail`

`render: "compact" | "detail"` — свойство размещения, не сущности. `compact` — как
в v1. `detail` — описание и члены (значения `enum`, сигнатуры) внутри бокса.

Именованный профиль выбран затем, чтобы список расширялся без правки контракта.

Делать последним: показывать нечего, пока утилита не извлекает члены.

## 5. Правило, которое не обсуждается

**Координаты правит только владелец руками.** Ни агент, ни скрипт, ни «умная»
перераскладка при открытии, ни восстановление после ошибки. Если вид выглядит
сломанным — сообщить человеку, а не чинить.

Автоматической раскладки в редакторе не появляется. Вытаскивание из базы кладёт
элемент в подсказанное место — дальше двигает человек.

---

## 6. Открытые вопросы

1. **Имя пакета.** Взято `spla-atlas-editor` в пару к `spla-atlas`. Переименование
   тривиально, пока нет кода.
2. **Порог осмысленности призраков.** При степени узла больше десятка это
   макароны. Нужен ли предел, после которого метка открывает сразу список —
   решать на живой схеме, не заранее.
3. **Язык интерфейса против языка схемы.** Тексты схемы переключаются
   (`text.en` / `text.ru`); подписи самого редактора русские. Связывать или
   разводить — не решено.
4. **Вид с несколькими проектами.** Контракт не запрещает и не описывает. Пока
   считаем, что вид принадлежит одному проекту.
