# PLAN_20260820_apps — хаб проектов: костяк и базовый UI

Статус: **в работе**

Реализует [`ADR_20260820_apps_project-hub`](../adr/ADR_20260820_apps_project-hub.md).

Цель первого этапа — **костяк и базовый UI, но работающие так, как задумано**, чтобы не переделывать
целиком во второй раз. Косметика откладывается, архитектурные швы — нет.

---

## Порядок и его причина

Этапы 1–2 ничего не меняют в поведении и снимают дублирование, на которое иначе лягут новые копии.
Этап 3 — единственный новый концепт, от него зависят 4, 5 и 6. Этап 7 — UI поверх готового.

Опорное правило: **регистрация — вид, а не зависимость.** На каждом этапе проверяется, что всё
работает при мёртвом хабе.

      функционально верно, но 127 в POSIX традиционно значит «команда не найдена» и может сбить с
      толку скрипты. Понять, откуда он берётся, и при необходимости привести к чему-то обычному.

## Этап 5. UI-процесс роли `hub`

- [x] Режим UI-бинарника: `--hub`, окна нет, только трэй, `ShutdownMode.OnExplicitShutdown`.
- [x] Именованный мьютекс — **сессионный, не машинный** (см. ниже).
- [x] Обычные окна проектов **перестают создавать трэй**; вместо этого каждое просит поднять оболочку.
- [x] «Open» из трэя: спрашивает хаб про окно на проекте, поднимает его, иначе запускает новое.
- [x] Разбор аргументов UI переведён на Spectre (`[project]`, `--hub`), с `AttachConsole` для текста.
- [x] Unload → **Close** и **Kill** отдельными пунктами, адресуют проект целиком.
- [x] Меню сгруппировано по проекту, а не по участнику — иначе открытый проект показывался бы дважды.

Сделано: `be8a8ac`.

Мьютекс сессионный сознательно: имя без префикса живёт в пространстве имён сессии терминального
сервера. Это и есть верная область — у двух пользователей на одной машине по RDP свои области
уведомлений, и машинный замок оставил бы второго вообще без трэя. Заодно закрывает вопрос из
«не проверено» этапа 3.

Проверено headless:

| Проверка | Результат |
|---|---|
| Два запуска `--hub` | выжил **один процесс** — исходная жалоба закрыта |
| Хаб поднялся | `/health` отвечает, реестр пуст и корректен |
| `--help` у UI | полный текст, код 0, **окно не открывается** |
| Неизвестная опция | ошибка с указателем на неё, ненулевой код, окна нет |

**Нужны глаза (headless не проверить):**

- [ ] Значок в трэе действительно один при трёх открытых проектах, меню читаемо.
- [ ] «Open» на уже открытом проекте поднимает окно, а не плодит второе. Здесь ожидается **частичный
      результат**: Windows отдаёт передний план только процессу, который его уже держит. Оболочка
      трэя интерактивна, но заявку исполняет *целевой* процесс, поэтому свёрнутое окно развернётся
      надёжно, а поверх чужого полноэкранного может лишь мигнуть кнопкой в панели задач. Полное
      решение — `AllowSetForegroundWindow` со стороны трэя перед ретрансляцией; не делал.
- [ ] Окно открывается при мёртвом хабе (перенесено с этапа 3).
