# PLAN_20260820_apps — хаб проектов: костяк и базовый UI

Статус: **в работе**

Реализует [`ADR_20260820_apps_project-hub`](../adr/ADR_20260820_apps_project-hub.md).

Цель первого этапа — **костяк и базовый UI, но работающие так, как задумано**, чтобы не переделывать
целиком во второй раз. Косметика откладывается, архитектурные швы — нет.

---

## Порядок и его причина

Этапы 1–2 ничего не меняют в поведении и снимают дублирование, на которое иначе лягут новые копии.
Этап 3 — единственный новый концепт, от него зависят 4, 5 и 6. Этап 7 — UI поверх готового.

Опорное правило: **регистрация — вид, а не зависимость.** На каждом этапе проверяется, что всё
работает при мёртвом хабе.

---

## Этап 1. Платформенная библиотека

Новый проект без UI-зависимостей (кандидат: `SPLA.Platform` в `src/core/`).

- [ ] Создать проект, добавить в `SPLA.slnx`.
- [ ] Запуск браузера: по умолчанию системный, с возможностью адресно (Chrome/Edge), `try/catch` на
      отсутствие десктопа. Windows — путь из реестра или `ShellExecute`; macOS — `open -a`;
      Linux — `xdg-open`.
- [ ] Переезд `WindowsShellIntegration` из `SPLA.UI.Avalonia`.
- [ ] Общий запуск себя: одна реализация вместо копий в `MainWindow.LaunchProject` +
      `TrayIconService.LaunchProject` + `ResolveSelfInvocation` (обе копии).
- [ ] Кнопку «открыть в браузере» в `MainWindow` перевести на хелпер.

Проверка: UI и CLI собираются, кнопка браузера работает, ассоциация файлов не сломана.

## Этап 2. Единый разбор аргументов

- [ ] `config.UseStrictParsing()` в `SPLA.CLI/Program.cs` — **отдельным коммитом**, это изменение
      поведения: опечатка в опции перестаёт молча игнорироваться.
- [ ] Перевести `ps`, `stop`, `hub`, `init` на Spectre. Ключевое ограничение: они по-прежнему **не
      должны резолвить и лочить проект** — сохранить перехват до общего бутстрапа, заменить только
      рукописный разбор и рукописный help.
- [ ] Убрать копии `Option(args, "--x")`.

Проверка: `--help` у каждой команды, неизвестная опция даёт ненулевой код, `ps`/`stop` работают из
произвольного каталога и не создают лока.

## Этап 3. Учёт участников (ядро)

- [ ] Роль записи в реестре: `agent` | `window` | `hub`. Расширение `RegisterFrame` и записи в
      `RegistryHub`, фильтрация в `List()`.
- [ ] Канал управления получает адресацию не только `stop`: как минимум `focus` и `close`.
- [ ] Переписать комментарий-инвариант в `RegistryHub` (ADR §4) — он станет неверным.
- [ ] UI регистрируется как `window` при старте: проект, роль, адрес сервиса.
- [ ] Проверить, что окно открывается при недоступном хабе и не ругается.

Проверка: `spla ps` показывает окна наравне с агентами; хаб убит — всё работает, окна неадресуемы.

## Этап 4. Хаб умеет запускать

- [ ] Порождение инстанса на проекте (роль спавнера в хабе).
- [ ] CLI-команды поверх: перечислить, запустить, остановить, забыть из списка. Через `--registry`
      или локальный хаб по умолчанию.
- [ ] Отказ инстанса при активном ходе сохраняется; `--force` только явно.

Проверка: с голой консоли, без запущенного UI, поднять и погасить проект.

## Этап 5. UI-процесс роли `hub`

- [ ] Режим UI-бинарника: окно скрыто, трэй, роль `hub` в реестре.
- [ ] Именованный мьютекс: не первый — достучался и вышел.
- [ ] Обычные окна проектов **перестают создавать трэй** (`App.OnFrameworkInitializationCompleted`).
- [ ] «Open» из трэя: окно есть — вынести на передний план (работает, потому что процесс
      интерактивный); нет — запустить.

Проверка: три открытых проекта = один значок; повторный «Open» не плодит окна.

## Этап 6. Close, Kill и конец сироты

- [ ] «Unload» в трэе заменить на **Close** (вежливо) и **Kill** (`--force`).
- [ ] Close закрывает агента **и его окна** — через §3.
- [ ] Отказ при активном ходе показать человеку, а не проглотить: `TrayIconService` сейчас глушит все
      ошибки (`catch { }` в трёх местах), «нажал и ничего не произошло» — это оно.
- [ ] Веб-клиент: ретрай с нарастанием вместо 1.5 с по кругу и явное состояние «агент ушёл» с
      предложением поднять заново. Механика есть — `Dispose` ребёнка не убивает, инстанс
      переприсоединяется через лок.

Проверка: Close при активном ходе отказывает и говорит почему; Kill закрывает всё; окно после смерти
агента предлагает действие, а не молчит.

## Этап 7. Страница хаба

- [ ] Раздача бандла из `RegistryHubHost` — зеркало `SplaServiceHost` `MapGet("/{**path}", …)`,
      обе в одной сборке.
- [ ] Surface `hub`: список проектов (MRU через `project.recent`), состояния из
      `/registry/watch`, действия — открыть, переключить, Close, Kill, новый проект, забыть.
- [ ] «Открыть» и «Переключить» — два разных действия (ADR §6). Локально «переключить» =
      перенацелить окно на инстанс другого проекта, **не** ребайнд внутри одного `serve`.
- [ ] Доступно и как окно (`SurfaceWindow`), и в браузере — через хелпер этапа 1.

Проверка: страница работает при отсутствии запущенных проектов; открытие и переключение различимы по
результату.

## Проверки, не привязанные к этапу

- [ ] **Догон дельт**: вернуться в чат посреди хода и убедиться, что экран не теряет кусок вывода.
      Если теряет — отдельная задача, не расширять этот план.
- [ ] Поведение трэя при нескольких сессиях Windows (RDP, быстрое переключение пользователей).

## Не входит

- Версионный скос живучего хаба — к v1 (ADR §10).
- Мигание иконки трэя через `null` — работает, косметика.
- Удаление мультипроектного `AgentRuntimeRegistry` — он нужен серверу.
