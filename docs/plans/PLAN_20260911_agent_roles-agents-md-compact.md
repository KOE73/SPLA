# PLAN_20260911_agent — роль при создании чата, режим AGENTS.md, правила по дереву, сжатие

Статус: **в работе — не начато** (2026-09-11).

Реализует два решения:

- [`ADR_20260911-2_agent_agents-md-scopes`](../adr/ADR_20260911-2_agent_agents-md-scopes.md) —
  режим `agents_md`, правила AGENTS.md по дереву папок, пометки областей, запрет записи до правил;
- [`ADR_20260911-3_agent_compaction`](../adr/ADR_20260911-3_agent_compaction.md) — `/compact`
  через `ContextRetention.Never`.

Читать план без них бессмысленно: здесь порядок работ, там причины. Если по ходу работы факт в коде
расходится с ADR — **остановиться и спросить владельца** (см. «Точки остановки»), а не подгонять
решение молча.

Весь механизм областей — эвристика по дереву папок: область = каталог, в котором лежит AGENTS.md,
действует на всё поддерево, глубже — главнее, соседи независимы. Каждое место, где нужно решить
«чьё это правило», решается только этим, без исключений по типу файла или инструмента.

## Волна 3 — правила по дереву папок

- [ ] `ContextAssembler.ShouldSend` → `false` для пометок.
- [ ] `Conversation.ShouldPersist` → `true` для пометок **всегда**, независимо от `saveToolCalls`.
- [ ] `ChatSessionMessage`: поле `scope_marker`; маппинг туда и обратно (найти, где

- [ ] DTO сообщений для окна: пометки в список сообщений `chat.opened` **не отдавать** (волна 3 без

- [ ] Тесты: пометка не уходит в модель, переживает save/load, обрезка её убирает, ответвление
      копирует.

### 3.2. Поиск цепочки

- [ ] `AgentsScopeResolver` (в слое, где живёт рабочая область/`IWorkspace` — проверить по
      `agents/structure.md`; не в плагине):

        каталог) с файлом `AGENTS.md`, корень исключён; `null`, если нет;

      - чтение файла с кэшем по (путь, mtime);
      - путь вне корня проекта, путь под `mnt/`, абсолютный путь другого диска → `null`.
- [ ] Нормализация путей — тем же способом, что файловые инструменты (`IWorkspace`/`MapPath`), чтобы

- [ ] Имя файла — только `AGENTS.md`. Без вариантов (`agents.md`, `CLAUDE.md`) — если нужно, это

- [ ] Тесты на дереве из ADR (`/`, `src/`, `src/backend/`, `src/frontend/`): цепочки, соседи не

### 3.3. Ступень конвейера

- [ ] `AgentsScopeStage : IToolMiddleware`, стадия `Policy`, рядом с `ZoneShadowStage` (там же
      регистрация в `ToolPipelineBlueprint` — посмотреть, как добавлен `ZoneShadowStage`).
- [ ] Какие вызовы: те, у которых в аргументах `path` (все файловые инструменты `SPLA.MCP.BasicTools/
      FileSystem` берут именно `path`). Разбор аргумента — общий с `EdgeClassifier` (вынести, а не
      копировать). Shell, SSH, сеть — не участвуют.
- [ ] Режим — из настроек сеанса (`AgentSessionScope.Current?.Settings ?? проектные`); `Ignore` →
      ступень пропускает вызов без действий.
- [ ] Логика:
      1. `scope = DeepestScope(path)`; `null` → дальше по конвейеру;
      2. покрыта ли область: есть пометка с `ScopeMarker == scope` или с путём внутри `scope`

      3. не покрыта → добавить пометку в переписку сеанса;
      4. вызов **пишет** (эффект `Write` у `EdgeClassifier`) и область была не покрыта → вернуть отказ,
         вызов не выполнять;
      5. иначе → дальше по конвейеру.
- [ ] Доступ к переписке сеанса: `IAgentSession` получает `Conversation? Conversation => null`
      (член по умолчанию, как `Settings`); `ChatRuntime`'s `AgentSession` и сеанс порождённого
      подагента его реализуют. Не ходить через `MarkManager.Target`.
- [ ] Потокобезопасность: пачка вызовов и фоновые вызовы (`BackgroundStage`) могут прийти
      одновременно — проверка «покрыта ли» и добавление пометки под одним замком; две параллельные
      записи в одну новую область дают одну пометку и два отказа.
- [ ] Текст отказа — английский, короткий, по `sys_prompt_rules.md`; смысл: «project rules for

      `"agents rules not loaded"`.
- [ ] Защита от циклов генерации: отказ + повтор — два одинаковых вызова подряд. Проверить пороги
      (`llm-loop-guard`, стадия Output); если пара её задевает — остановиться и спросить владельца.
- [ ] Тесты: чтение в новую область → выполнено, пометка есть; запись в новую → отказ, пометка есть,
      повтор → выполнен; запись в покрытую → выполнена; `ignore` → ни пометок, ни отказов; две
      параллельные записи → одна пометка.

### 4.2. Операция

- [ ] `ChatRuntime.CompactAsync(CancellationToken)`:
      1. отказ посреди хода (как `TrySaveIdle` у ответвления);
      2. хвост: последние `CompactTailMessages` реплик человека; граница — перед репликой человека;
         если сжимать нечего (история короче хвоста) — вежливый отказ;
      3. вход модели: `ContextAssembler.Assemble` до хвоста, без пометок, меток, `IsEphemeral`; модель —
         модель чата; без инструментов; промпт из ADR §2.4 (встроенный ресурс, например
         `SPLA.Agent/Prompts/compact.md` — посмотреть, где живут похожие); сверить с
         `sys_prompt_rules.md`;
      4. `Never` + `CompactedBy` всем сжатым, кроме пометок (`ScopeMarker`) и меток;
      5. вставить пересказ перед хвостом (`Conversation` — метод вставки перед сообщением, по образцу

      6. сохранить чат; опубликовать изменение через поток событий сеанса (`agents/chat-feed.md`) —
         окна получают свежий снимок.

## Точки остановки — спросить владельца, не решать самому
