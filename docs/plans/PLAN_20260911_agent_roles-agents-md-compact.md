# PLAN_20260911_agent — роль при создании чата, режим AGENTS.md, правила по дереву, сжатие

Статус: **волны 0–5 реализованы; открыт один пункт** (2026-09-11) — волна 4.4 «живой `/compact`
на уже загруженной модели, качество пересказа показать владельцу» не проведена в этом окне (нет
следов в коммитах волны 4); плюс известный, не закрытый в этом плане пробел из волны 3.4: у
закреплённого (pinned skill) подагента промпт не пересобирается, так что отказ записи в новую
область не долетает до его следующего вызова (см. волну 3.4 ниже). Всё остальное — код, тесты,
документация — сделано и сверено с кодом.

Реализует два решения:

- [`ADR_20260911-2_agent_agents-md-scopes`](../adr/ADR_20260911-2_agent_agents-md-scopes.md) —
  режим `agents_md`, правила AGENTS.md по дереву папок, пометки областей, запрет записи до правил;
- [`ADR_20260911-3_agent_compaction`](../adr/ADR_20260911-3_agent_compaction.md) — `/compact`
  через `ContextRetention.Never`.

Читать план без них бессмысленно: здесь порядок работ, там причины. Если по ходу работы факт в коде
расходится с ADR — **остановиться и спросить владельца** (см. «Точки остановки»), а не подгонять
решение молча.

Весь механизм областей — эвристика по дереву папок: область = каталог, в котором лежит AGENTS.md,
действует на всё поддерево, глубже — главнее, соседи независимы. Каждое место, где нужно решить
«чьё это правило», решается только этим, без исключений по типу файла или инструмента.
