## 12. Порядок работ

1. **Контракт.** Один метод, `LlmTurnContext` / `Result`, `ILlmGateway`, конвейер, чертёж,
   `Permissive`-политики. Провайдер пока один. Поведение не меняется, тесты зелёные.
   Радиус: `ILLMService`, `AgentRuntime`, `ConversationOrchestrator`, `SpawnedAgentRunner`, четыре
   тестовые заглушки, оба воркера.
2. **Контент и ключи.** Каноническая контент-модель + сериализаторы; `api_key` → `credential:`;
   поле вырезается из схемы, DTO и протокола.
3. **Учёт.** `rawUsage` + справочник типов + `IUsageLedger`; файловая реализация, схема — целевая.
4. **Провайдеры плагинами.** LM Studio переезжает в плагин; `OpenAiWire`; Google → OpenAI → Anthropic.
5. **Сервер.** `RoleBased`-политики, server-scope и user-scope подключения, EF-ledger, квоты.
6. **Воркеры.** `connection` в VisionAgent, два `.cmd` (локальная и облачная), стоимость кадра в
   подвале.

## 14. Состояние реализации

**Этап 1 — сделано.** `ILLMService` удалён, три метода схлопнуты в один `InvokeAsync`. В
`SPLA.Domain/Llm/` появились `LlmTurnContext` / `LlmTurnResult`, `ILlmClient` + `ILlmClientResolver`,
`ILlmGateway`, `ILlmMiddleware` со стадиями, `LlmPipelineBlueprint` и `TurnOutcomeMiddleware`.
`LMStudioClient` стал `ILlmClient`; `AgentRuntime.Llm` — это `ILlmGateway`, испечённый из чертежа.
Запрет плагинам на стадии `Accounting` и `Transport` реализован в `UseFromPlugin` (бросает
исключение), порядок задаётся стадией, а не порядком регистрации. Провод LM Studio теперь возвращает
реальное имя модели из поля `model` ответа, так что `model: auto` больше не попадает в учёт как
«auto». Сборка чистая; тесты: 272 проходят, 2 падают — те же две, что падают на нетронутом HEAD.

**Секреты — сделано (часть этапа 2).** Области стали `user | project | shared`, поиск и перекрытие
между областями убраны полностью, область входит в саму ссылку
(`secret:<scope>:<key>[#field]`), а весь синтаксис живёт в одном классе `SecretRef`. У записей
появился ACL (владелец + аддитивные выдачи `Use`/`Manage` пользователям и группам), проверяемый **в
момент резолва**, а не только при перечислении; ACL лежит открытым текстом рядом с хранилищем, чтобы
перечисление не расшифровывало. Умолчаний по области нет нигде: CLI требует флаг, протокол отклоняет
запрос без области, панели SQL/SSH и панель секретов заставляют выбрать. Каждая запись в списке несёт
свою область, готовую ссылку и `canManage`.

Осталось по §12: `api_key` в схеме подключений (этап 2), учёт (этап 3), провайдеры плагинами
(этап 4), сервер (этап 5), воркеры (этап 6).
