# PLAN_20260804_agent — переписывание скилов под библиотечную модель

**Статус: открыт.** Реализация [`ADR_20260804_agent_skills-library`](../adr/ADR_20260804_agent_skills-library.md).

Цель в одну фразу: **скил существует независимо от того, знает ли о нём модель — фонд, каталог и
выдача становятся тремя разными вещами.**

---

## Решения по объёму (приняты до начала работы)

**1. Совместимости нет — и мы этим пользуемся.** Внешних клиентов, опубликованного протокола и чужих
`.spla` не существует. Ключи yaml, имена сообщений и раскладка папок меняются свободно, старое
удаляется, а не депрекейтится. Миграций не пишем.

**2. Переименование — отдельным этапом и целиком механическое.** Смешивать его с логикой нельзя:
диффы станут нечитаемыми, а красные тесты — необъяснимыми. Этап 2 не меняет поведения ни в одной
строке.

**3. Ресурсы идут первыми, до всей библиотечной работы.** Они ни от чего не зависят, а без них
`SPLA.Skills` неработоспособен в принципе — то есть проверять остальные этапы будет не на чем.

**4. Библиотекарь-подагент — последним из «умного».** Тэговый отбор закрывает большинство случаев;
подагент имеет смысл только когда есть на чём мерить выигрыш.

---

## Этап 1. Приложения к книге

Без этого `SPLA.Skills` не работает: `SKILL.md` на шаге 0 требует `references/package-contract.md`, а
механизма прочитать его нет ни одного.

- [ ] `ISkillSource`: `ListResources(skillRef)` и `ReadResource(skillRef, relPath)`. Резолв — внутри
      источника, с той же защитой от выхода за корень, что уже в `DirectorySkillSource.Resolve`.
- [ ] `DirectorySkillSource`: реализация для папочной раскладки (всё рядом с `SKILL.md`, кроме
      самого `SKILL.md`).
- [ ] `PluginSkillSource`: то же для скилов, приезжающих с плагином.
- [ ] Инструмент `skill_read_resource`, `ToolScope.Skill`. Доступен **только при активном скиле** и
      **только для его собственных ресурсов** — это формуляр выдачи, а не файловый доступ.
- [ ] В блок `=== ACTIVE SKILL ===` добавить список доступных приложений. Иначе модель не знает, что
      можно спросить.
- [ ] Решить явно: приложения снимаются при активации (как тело) или тянутся живой ссылкой на
      источник. Влияет на случай «источник исчез, книга на руках».
- [ ] Тесты: чтение, выход за корень, чтение чужого ресурса, чтение без активного скила.

**Проверка этапа:** `linux-host.capture` из `SPLA.Skills` доходит до конца шага 0.

## Этап 3. Тэги и уровень источника

- [ ] Фронтматтер: `tags: [...]`. Нормализация — нижний регистр, kebab-case, дедупликация.
- [ ] `TagVocabulary`: полный словарь фонда, доступен UI и библиотекарю.
- [ ] `SourceLevel`: `вне каталога / только по поиску / в каталоге / на полке`. По образцу уже

      это перенос существующего понятия, а не новое.
- [ ] `CatalogView`: что уходит модели. Порог — когда доступных скилов больше N, каталог
      сворачивается в облако тэгов автоматически.
- [ ] `SkillsContributor` печатает облако тэгов вместо полного списка, когда уровни так говорят.
- [ ] Фасеты по тэгам в панели настроек.

**Проверка этапа:** 100 скилов дают каталог в промпте меньше 200 токенов.

## Мелкие долги, которые чинятся по дороге

- [ ] `watcher.Error` не подписан: `git pull` в репозитории на сотни скилов даёт
      `InternalBufferOverflow`, события теряются молча, hot reload умирает до рестарта.
- [ ] `Enumerate()` читает каждый файл целиком на каждый `Rebuild`. Нужен кэш по mtime+size и разбор
      только шапки.
- [ ] `SkillManager.IsSkillActive` в продакшене никем не присваивается (только в тестах) — либо
      подключить, либо удалить: тело и так пиннится.
