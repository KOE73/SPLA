# SPLA.CLI — полный справочник по командам

[English](README_CLI.en.md)

> **Этот файл обязан отражать код.** Он описывает ВСЕ команды и флаги CLI. Меняешь разбор аргументов
> в `src/apps/SPLA.CLI/` — `Program.cs`, `Cli/CliBootstrap.cs`, `Cli/ServeCommand.cs`,
> `Cli/SecretCommands.cs`, `Cli/ChatCommands.cs`, `Cli/InteractiveRepl.cs` — правь оба справочника
> (`docs/README_CLI.ru.md` и `docs/README_CLI.en.md`) в том же коммите. Справочник, который врёт,
> хуже отсутствующего: по нему человек выполняет команду и получает `Scope is required` вместо
> результата.

Исполняемый файл называется **`SPLA.CLI.exe`**. Ниже он для краткости `spla` — как это устроить,
см. [Алиас в Windows](#алиас-в-windows).

## Как выбирается проект

Проект определяется ДО разбора команды, по первому аргументу:

| Запуск | Что берётся |
|--------|-------------|
| `spla <путь>.spla …` | именно этот файл; **если файла нет — он будет создан** (`ScaffoldIfNew`) |
| `spla chat …` | поиск `*.spla` вверх от текущего каталога |
| всё остальное, включая запуск без аргументов | поиск `*.spla` вверх от текущего каталога |

Если файл проекта не найден, CLI работает на глобальных настройках (`~/.spla/defaults.yaml`) — это
рабочий режим, а не ошибка. Когда проект найден, **рабочий каталог процесса меняется на `workspace`
проекта**, и относительные пути дальше считаются от него.

При старте печатается: файл проекта, имя проекта, workspace, endpoint модели, режим агента и число
зарегистрированных инструментов.

## Команды

### Без команды — интерактивный REPL

```
spla
spla myproject.spla
```

Создаёт новый чат и входит в цикл «строка → ход агента». Внутри REPL:

| Ввод | Действие |
|------|----------|
| `/skills` | список доступных скиллов: `[on]`/`[off]`, id, описание |
| `/skills load <id>` | загрузить тело скилла в контекст текущего чата |
| `exit` / `quit` | выход |
| пустая строка | выход |

### `serve` — WebSocket-сервис

```
spla serve [--port <N>] [--bind <адрес>] [--token <строка>] [--repl] [--new-chat "<текст>"]
```

| Флаг | По умолчанию | Смысл |
|------|--------------|-------|
| `--port <N>` | `5050` | TCP-порт |
| `--bind <адрес>` | `127.0.0.1` | интерфейс |
| `--token <строка>` | нет | токен доступа к сокету |
| `--repl` | выкл | параллельная консольная сессия к тому же рантайму, что и у сокет-клиентов |
| `--new-chat "<текст>"` | нет | сообщение, с которого начинается первый чат |

Останов — Ctrl+C. С `--repl` слова `exit`/`quit` останавливают сервис; если stdin просто закрылся,
сервис продолжает работать.

Привязка не к loopback **без** `--token` выводит предупреждение и не блокируется: любой, кто достанет
до порта, управляет агентом. Это осознанное «предупреждаем, но не решаем за тебя» — но в сети так
делать не надо.

### `secret` — хранилище секретов

```
spla secret list                          --user | --project | --shared
spla secret set    <key> [--field <имя>]  --user | --project | --shared
spla secret delete <key> [--field <имя>]  --user | --project | --shared
```

Правила, из-за которых команда чаще всего не срабатывает с первого раза:

- **Флаг области обязателен и дефолта не имеет.** Так сделано намеренно: инструмент, выбирающий
  область сам, — это способ получить один ключ в двух хранилищах, где одно тихо затеняет другое.
- **`--field` учитывается только первый.** Одно поле за вызов; два поля — два вызова.
- **Значение вводится скрытым промптом**, в аргументах командной строки его передать нельзя — иначе
  оно осело бы в истории оболочки. По той же причине `list` печатает только ключи и имена полей,
  никогда — значения.
- `set` **дописывает** поле в существующую запись, не затирая соседние.
- `delete` с `--field` удаляет одно поле; без него — запись целиком. Удаление последнего поля удаляет
  запись.
- `--project` требует открытого проекта, иначе — отказ с подсказкой.

Область попадает в ссылку, которой на секрет ссылается конфиг: записанный с `--user` ключ
`my-host-ssh` адресуется как `secret:user:my-host-ssh`.

Поля, которые понимает SSH-плагин: `user`, `password`, либо `private_key` (+`passphrase`).

Коды возврата: `0` — успех, `1` — не найдено (при `delete`), `2` — ошибка в аргументах.

### `chat` — сохранённые чаты

```
spla chat list
spla chat open <id>
spla chat fork <id> [--model <имя>]
```

- `list` — id, заголовок, время изменения.
- `open <id>` — открыть чат и войти в REPL. **Если id не найден, молча создаётся новый чат** — этого
  стоит ожидать, отдельного сообщения об ошибке нет.
- `fork <id>` — копия чата, опционально с другой моделью. `--model` разбирается позиционно: он
  должен идти сразу после id (`chat fork <id> --model <имя>`) и пишется строчными буквами.
- `spla chat` без подкоманды печатает строку использования.

## Алиас в Windows

Копировать `SPLA.CLI.exe` в другое место **нельзя**: apphost ищет свою управляемую сборку рядом с
собой и в чужом каталоге просто не запустится. Переименование на месте работает, но каждая сборка
создаёт `SPLA.CLI.exe` заново, и переименование придётся повторять.

Рабочий вариант — шим `spla.cmd`. Он уже лежит в корне репозитория: добавь корень в `PATH` (или
скопируй файл в каталог, который там уже есть) — и `spla ...` работает откуда угодно.

Он сам ищет exe в порядке: переменная `SPLA_CLI` → `.publish\work` → `bin\Release` → `bin\Debug`,
поэтому переживает и пересборку, и публикацию. Если сборка лежит в стороне:

```bat
set SPLA_CLI=D:\где-то\SPLA.CLI.exe
```

Каталог шим не меняет намеренно: CLI ищет `*.spla` вверх от текущего каталога, и `cd` внутри шима
тихо подсунул бы не тот проект.

Альтернатива для PowerShell — строка в `$PROFILE`:

```powershell
Set-Alias spla 'C:\путь\к\SPLA.CLI.exe'
```

`doskey` не предлагаю: он живёт только внутри сессии `cmd` и в PowerShell не действует.
