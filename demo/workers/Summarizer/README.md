# Summarizer — пакетный пересказ документа на SPLA Runtime

Третий демо-хост `SPLA.Runtime` без CLI/сервиса/UI: берёт из папки один документ и прогоняет по
нему **матрицу «каждый вариант промпта × каждая модель»**, складывая каждый результат обратно в ту
же папку под именем, по которому потом понятно, чем и когда он сделан.

Задача, из которой он вырос: расшифровка совещания и вопрос «а вытянет ли это маленькая модель».
Ответ на такой вопрос — не один запуск, а таблица запусков, которую можно перечитать через неделю.

## Что делает

Цикл: **подобрать исходник → для каждой модели загрузить её → для каждого промпта один чистый чат
→ ответ в файл с метаданными**.

- Промпт варианта — не файл проекта, а `settings.CustomPrompt`, подменяемый перед ходом. Контекст
  пересобирается на каждом вызове LLM, поэтому подмена «на живом» и есть весь механизм: один
  рантайм обслуживает всю матрицу.
- Каждая ячейка — **новый чат**. Сравнивать попытки имеет смысл только когда они независимы.
- `--lm` прогоняет локальные модели LM Studio: перед ячейкой модель загружается через
  `IModelManagementService`, предыдущая выгружается. Один локальный рантайм с десятком скачанных
  моделей превращается в десяток целей.
- В начало каждого результата пишется YAML front matter: модель, эндпоинт, промпт, окно контекста,
  токены, время, число брошенных стражем генераций.
- `capabilities: []` в проекте: у агента нет ни одного инструмента. Это и самый короткий системный
  промпт, что важно на 4B-модели, и гарантия, что «пересказчик» ничего не тронет.

## Запуск

```bash
dotnet run --project demo/workers/Summarizer -- "<папка с документом>"
```

Или собранным exe:

```bash
Summarizer.exe "C:\Director\20260810 110209 Совещание по ЭТН" --prompt short --lm all
```

Файл проекта ищется **вверх** от указанной папки — документ лежит в подпапке, манифест в корне.
Полный список ключей — `Summarizer.exe --help`.

Сначала стоит посмотреть, что нашлось, и во что это развернётся:

```bash
Summarizer.exe "<папка>" --list      # исходник, варианты промптов, модели
Summarizer.exe "<папка>" --dry-run   # плюс имена будущих файлов
```

## Ключи секции `summarize:`

| Ключ | Значение |
|------|----------|
| `prompts_dir` | папка с вариантами промптов; каждый `*.md` — один вариант (`README.md` и `_*` не считаются) |
| `source_extensions` | что считать исходником, по порядку предпочтения; берётся расширение, давшее ровно один файл |
| `exclude_containing` | подстроки в имени, при которых файл исходником не считается (иначе резюме станет исходником) |
| `output_marker` | слово в имени результата: `<исходник> - <marker> <дата-время> <промпт> <модель>.md` |
| `prompt_place` | `system` (родной для SPLA) / `user` (рядом с данными) / `both` |
| `user_frame` | ход пользователя; `{document}` обязателен, `{prompt}` подставляется при `user`/`both` |
| `front_matter` | писать блок метаданных в начало результата |
| `echo`, `show_reasoning` | транслировать поток модели / её размышления в консоль |
| `timeout_seconds` | предел на одну ячейку |
| `skip_if_too_large` | не пытаться, если документ заведомо не влезает в окно модели |
| `models`, `lmstudio_models`, `prompts` | что прогонять, когда в командной строке не задано ничего |

## Живой пример

Рабочий проект под эту задачу — `C:\Director\Director.spla`: варианты резюме в
`ResumePrompts\`, по папке на совещание, результаты рядом с исходником.
