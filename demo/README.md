# demo/ — примеры SPLA

Демо разделены на четыре типа:

- [`workers/`](workers/) — автономные приложения-воркеры на `SPLA.Runtime`;
- [`projects/`](projects/) — готовые демо-проекты для запуска в SPLA;
- [`prompts/`](prompts/) — промпты для проверки инструментов на живом стенде;
- [`mcp-servers/`](mcp-servers/) — runbook'и подключения внешних (foreign) MCP-серверов: SPLA как
  клиент, а не как хост инструментов.

## Workers

Каждый worker — маленькое самостоятельное приложение, которое подключает
`src/agent/SPLA.Runtime`, открывает обычный файл проекта `.spla` и получает
полноценного агента **без CLI, сервиса и UI**. Это и есть критерий правильности
границы рантайма: стороннее приложение + проект + модель = живой агент.

| Демо | Что делает |
|------|-----------|
| [VisionAgent](workers/VisionAgent/README.md) | Кадры с USB-камеры / RTSP / видеофайла → анализ кадра моделью (время события, горное оборудование, номера) → консоль, по кругу. |
| [LogSentry](workers/LogSentry/README.md) | Хвост лог-файла → пачки подозрительных строк → триаж-вердикт (ИНЦИДЕНТ/ШУМ/НАБЛЮДАТЬ) → консоль. |
| [Summarizer](workers/Summarizer/README.md) | Документ из папки → матрица «каждый вариант промпта × каждая модель» (включая поочерёдную загрузку локальных моделей LM Studio) → файлы результатов рядом с исходником. |

Общий паттерн любого такого хоста:

```csharp
var settings = ConfigLoader.LoadAndResolve("my.spla");   // проект
using var runtime = new AgentRuntime(settings, loggerFactory); // весь стек агента
var chat = new ChatRegistry(runtime).CreateNew("my task");     // чат
await chat.SendAsync(text, callbacks, permission, clarify, ct, images);
```

Свои настройки демо держат в собственной секции того же `.spla`
(стандартный загрузчик незнакомые секции игнорирует) — один файл проекта
остаётся единственной точкой входа.

## Prompts

Промпты, которыми инструменты проверяются на живом стенде, а не в юнит-тестах. Юнит-тест отвечает
на вопрос «делает ли код то, что задумано»; такой промпт — на другой: понимает ли модель, что ей
дали, и внятно ли инструмент отказывает, когда должен отказать. Ни то, ни другое не закрывается в CI.

| Набор | Что проверяет |
|-------|---------------|
| [sftp-transfer](prompts/sftp-transfer/) | передача файлов по SFTP и контейнеры `.tar` — включая отказы: лимиты, границы путей, запрет записи на read-only хост. |

Каждый набор — это SETUP (что настроить, иначе не поедет) и PROMPT (текст в чат), на русском и
английском.

## MCP servers

Здесь SPLA не хост инструментов, а клиент — подключается к чужому MCP-серверу. У такого демо нет
одного правильного `.spla`: сервер, версия пакета и адрес всегда чьи-то конкретные. Вместо
запускаемого проекта — пошаговый **SETUP-runbook**, который агент может провести от начала до конца
сам, кроме одного явно помеченного шага: секрет заводит и вводит человек, вне чата.

| Набор | Внешний сервер | Что демонстрирует |
|-------|-----------------|--------------------|
| [azure-devops-code-search](mcp-servers/azure-devops-code-search/) | `@ahouben/azure-devops-mcp` (npm, stdio) | установка пакета, ссылка `secret:` в `.spla` вместо переменной окружения, обязательный полный рестарт после смены секрета, проверка без участия человека по логу и по `tools/list` |
