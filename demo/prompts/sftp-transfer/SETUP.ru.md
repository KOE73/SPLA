# SETUP — стенд для проверки SFTP-инструментов

[English](SETUP.en.md) · [Промпт](PROMPT.ru.md)

Без этой подготовки промпт не поедет: половина шагов проверяет отказы, а отказ «хост не настроен» —
не тот отказ, который мы хотим увидеть.

## Что нужно

1. **Linux-хост с работающим SSH** и включённой подсистемой SFTP. На типичном OpenSSH она уже есть —
   в `/etc/ssh/sshd_config` строка `Subsystem sftp internal-sftp` (или `.../sftp-server`).
   Проверка с Windows: если `ssh user@host` работает, то и `sftp user@host` почти наверняка работает.
   Администратор мог её отключить отдельно — тогда инструменты честно скажут, что подсистема
   недоступна, но тест на этом закончится.
2. **Второй хост, которому НЕ разрешена запись.** Он нужен ровно для одного шага — проверки, что
   `sftp_upload` отказывает без `allow_write`. Подойдёт любое устройство с SSH: роутер, NAS, вторая
   виртуалка. Настройки ему менять не надо, писать на него никто не будет.
3. **Учётка в secret-store**, а не пароль в конфиге. Пароль в `.spla` или в чате — это ровно то,
   чего плагин избегает by design.

## Секрет

Через CLI — по одному полю за вызов, значение вводится скрытым промптом (в аргументах его передать
нельзя, чтобы не осело в истории оболочки):

```bash
spla secret set my-host-ssh --field user --user
spla secret set my-host-ssh --field password --user
```

Область указывается обязательно и дефолта не имеет: `--user`, `--project` или `--shared`. Она же
попадает в ссылку из конфига — `secret:user:my-host-ssh` для области `--user`. Проверить:
`spla secret list --user`.

Исполняемый файл на самом деле `SPLA.CLI.exe`; про алиас `spla` и остальные команды —
[README_CLI.ru.md](../../../docs/README_CLI.ru.md).

Для ключа вместо пароля — поле `private_key` и, если ключ зашифрован, `passphrase`.
Всё то же самое есть на странице Settings → Secrets.

## Проект

В `.spla` проекта, из которого будешь запускать (пути в промпте относительны его `workspace`):

```yaml
permissions:
  read: allow
  write: allow
  shell: allow

plugins:
  ssh:
    enabled: true
    settings:
      timeout_seconds: 25
      hosts:
        my-host:                      # сюда пишем, allow_write обязателен
          host: 192.168.1.10
          credential: secret:user:my-host-ssh
          allow_write: true
        my-readonly-host:             # сюда НЕ пишем — это и проверяется
          host: 192.168.1.254
          credential: secret:user:my-readonly-host-ssh
```

`allow_write: true` на первом хосте нужен не для передачи файлов (скачивание разрешено всегда), а
для двух вещей: подготовительных команд, которые создают тестовый каталог, и шагов 17–19 с загрузкой
файла на хост.

Второму хосту `allow_write` **не ставить** — иначе шаг 16 пройдёт «успешно» и проверит ровно ничего.

## Перед запуском

- Имена хостов в промпте (`my-host`, `my-readonly-host`) замени на свои.
- Плагин должен быть собран и разложен: если SPLA был запущен во время сборки, он держит старую dll в
  памяти — **перезапусти его**, иначе увидишь поведение предыдущей версии.
- Проверь подключение: Settings → SSH → Test connection, или спроси у агента `ssh_list_hosts`.

## После прогона

Промпт заканчивается уборкой на удалённом хосте, но локально остаётся папка `check/` в проекте
(скачанные файлы и контейнер). Удали её руками, если не нужна.
