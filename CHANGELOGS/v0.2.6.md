# v0.2.6

## Summary


### An actor has a type, and the type is a boundary

Until now an agent was one thing configured one way, and a sub-agent was that same thing handed a
task. This cycle gives an actor a **role**: a settings type that lives in `roles/<name>.yaml` beside
the manifest and travels in git like any other project file. The manifest names the roles it accepts,
so a role file that arrives in a pull request and that nobody named does not act — the same rule, for
the same reason, as refusing to walk up the tree looking for configuration. Existing projects mean
exactly what they meant before: `agent:` is read as the default role.

The point of the type is that it **withholds**, not that it instructs. A named role governs the mode
of the run and actually narrows the tools the run is offered — a role a caller could widen by passing
`mode` would not be a boundary at all, and a reviewer told not to fix things needs the tools taken
away rather than the instruction repeated. An unknown role is refused with the available names listed,
because a silent fallback to the default runs the work with the wrong capabilities and looks like
success.

A chat can also find out who exists: `role_list` publishes name, mode and a one-line description, and
nothing else — the rest of a role body sits next to its capabilities and trusted domains, so handing
it out on request would route a security decision around the zone model. The directory is its own
capability and an *implied* one: it is the underside of addressing rather than a switch, required by
spawning and by corresponding, hidden from the settings panel, and refused if written in by hand.

### A spawned run is a session, not a footnote in memory

A sub-agent used to be an in-memory record that vanished on restart and could only be read once it
had finished. It is now an ordinary session with everything a chat already had — an id, a file on
disk, an inbox, a progress tree, token accounting — which is what makes it watchable mid-run rather
than only reportable afterwards. It stays off the human chat list and is bounded by retention instead:
finished sessions ring out oldest-first, and a run still in progress is never touched, however old.

The same change is what makes the rest of this cycle possible at all. Once a spawned run is a session,
two actors can address each other; once they can address each other, their exchange has a cost worth
accounting for.

### Actors write to each other, and the exchange runs down on its own

`agent_correspond` opens an address to another role. Once open, the chat grows its own reply tool for
that one correspondence — the tool name is the address, not a chat id buried in an argument list and
not a line of prompt asking the model to remember one. Calling it returns a delivery receipt and never
the answer: the correspondent's actual words arrive later, as an ordinary message on this chat's own
turn. A correspondent that goes quiet is announced and its reply tool stops appearing, rather than the
next call looking like a hallucinated tool name.

The address itself was tightened once it met real traffic. It used to be a role plus a free-text
topic the model retyped on every call, so a paraphrase or a typo silently founded a new correspondent
instead of reaching the existing one — and a Cyrillic topic normalised to a constant, which let
several correspondents claim the same reply tool and sent replies to whichever was found first. The
instance number now belongs to the chat rather than to the correspondence, so a third party has
something it can say out loud; purpose stays free text that explains and never addresses. And
`agent_introduce` lets one chat connect two others without either side spelling out a chat id.

The obvious failure mode is two actors that never run out of things to say on someone else's token
budget. So the exchange **decays by construction**: the wait before a reply wakes a turn doubles with
how many replies have crossed since a human last spoke, up to a ceiling past which a reply no longer
wakes a turn at all — it queues and rides whatever turn happens for another reason. The conversation
slows to the pace of outside events instead of being cut off mid-sentence. A hard cap exists purely as
an emergency stop that should never fire. The four numbers governing this are chosen, not yet
measured, and are overridable per role.

An older guard had to give way to make room for it. `self_feeding_cap` was a constant of 3 that
counted a turn as self-fed even when a correspondent's reply was what woke it, so an honest ping-pong
between two roles died on the third turn — before the regulator built for exactly that job ever got
to act. It is now a setting like the others, resolved per project and per role, and disabled by
default; a project that still wants an upper bound on an unattended run sets a number and has the old
behaviour back.

### Seeing who is talking, and who is being ignored

The chat list became a tree: a spawned session hangs under the chat that gave it its errand, tagged
with its role, instead of being hidden or mixed in among human chats. A sessions panel lists what is
running across the whole tree — role, parent, status, model, tokens. An incoming reply renders as
speech, "from `<role>`", the moment it lands; an outgoing one renders "to `<role>`" with its receipt
hidden. Underneath it is still an ordinary turn on the wire; only the rendering tells them apart.

Correspondences now survive a restart, because they live in the chat's session file rather than in a
running runtime, and each edge accumulates how much text actually crossed it. That measurement is
deliberately of the replies themselves and not of the turns they woke — a turn does many things, and
charging all of it to one edge would be a confident lie. The graph is then **drawn** rather than
listed: a role is a box with its totals, a pair of roles is one arrow however many chats it covers,
line weight carries volume, and layout is deterministic by column so the panel looks the same every
time it opens. Rendering it and looking is also what found two defects reading the code had not —
arrow heads that grew with the line, and an edge between two boxes in one column bowing outside the
viewBox where it was simply cut off.

### A chat that is archived stays archived

Opening an archived chat used to bring it back to life in everything but name — the list said
archived while the session ran. Opening one is now refused, and refused *legibly*: "Chat is archived",
not the misleading "Chat not found", so a client can tell a deliberate answer from a lost file.

Refusing to open it left nothing to look at, so the same cycle adds the way back in: `chat.read`
hands over an archived chat's history off disk, creating no runtime and registering no watch, and the
window shows it without a composer and without the status bar — which is entirely settings for a next
turn this chat will not take. That is a separate message type rather than a flag on `chat.open`, and
the reason generalises: `chat.opened` is a promise that the session is watchable and takes a message,
and reusing it here would put the burden of remembering the archived exception on every handler built
on that promise, one at a time, forever.

The same shape covers the other surface nobody may write to. A sub-agent's window shows its log and
its progress tree with no composer, because by the time a watcher decided to intervene the sub-agent
has changed its mind several times already. The difference worth stating is that this one is a rule
and not a house style: while its run is going, a message sent to a spawned session is refused by the
server, so a client that has never heard of sub-agents is refused on the same terms. Once the run
ends the session is an ordinary chat again, and the hidden composer is taste rather than prohibition.

### Configuration a person can reach, in the layer it belongs to

Roles were implemented before they were reachable: declaring one meant editing YAML in two places, and
"spawn a role" is not a feature anyone discovers that way. The roles editor shows both halves at once,
because hiding either hides a real state — the body is the file, and whether the role *acts* is the
manifest naming it, so a body nobody named is listed and switched off, and a name whose body will not
load is listed with empty fields rather than dropped. A save rewrites the whole set, which is what
makes a rename a move instead of a second copy. Every field may be left unsaid, and unsaid means
"whatever the project says" — which is why the fields had to become three-state words rather than
checkboxes: an unticked box and "not stated" look identical and mean different things.

Connections moved for a related reason. An endpoint plus a credential is a property of an account, not
of a repository, so it now resolves from three layers — shared, user, project — exactly as secrets do.
The layer is the *file* and never a field inside it, so nothing can disagree with where it was read
from, and a save rewrites every layer including the empty ones, or dragging an id from project to user
would copy it rather than move it. A role can then name which connections its chats may resolve a
model against; like islands, that is a selection and not a grant. Below both, models and roles gained
their own temperature and reasoning defaults, sitting between the project's `llm:` block and a chat's
own choice.

### The interface stops being several interfaces

Settings used to open in a window with its own frame, which read as a separate program when they are a
surface of the app the person is already in; they are now an overlay inside the window, raised the same
way from the web client and from the native menu. Underneath, the panels had drifted apart — each had
hand-rolled its own cards, carets, trashes and "+ Add", sometimes above the items so a freshly added
row appeared below the fold. A shared kit owns all of it now, including the order, and a card's chrome
is three variables, so the redesign ahead is one class rather than a sweep through every panel. Even
the plugin bundles ship a copy of the kit against the host's class names, so a host restyle still
reaches panels that cannot import from it.

The interface also speaks the reader's language throughout — shell, chat, dock, workspace, banners,
plugin panels and the native window frame, all through one dictionary keyed by the English source
text, so an untranslated string renders as English rather than as debris and the backend needed no
change at all. And the choice now survives a restart: it was being saved correctly and thrown away,
because an ephemeral loopback port makes every launch a new origin with an empty `localStorage`. It
lives in the machine layer now, deliberately not in the manifest — a language is a property of the
reader, not of the repository — and deliberately not broadcast, because on a shared server one
person's pick must not retitle somebody else's screen.

Reading a chat got the same kind of attention. The text has a reading measure a person can grab and
drag; the footer of knobs folds away, per window, since it is the next turn's settings and not the
conversation; and the log finally stays pinned to the bottom, by measuring the view with a
`ResizeObserver` instead of polling and stopping the moment a turn ends — which is why the last tokens,
a reflowing bubble or an image arriving with its real height used to leave the view a little short of
the end. One more invisible thing became visible: a rebuilt client could not reach the browser at all,
because serving no validator and no freshness let WebView2 keep replaying an index naming the old
bundle. Caching is now stated, and the two halves get opposite answers.

### The architecture diagram editor — experimental, as-is

**The diagram editor remains experimental and is shipped as-is:** it is under active development, its
model contract is still moving, and neither the file format nor the behaviour is stable between
releases.

Routing was rewritten rather than extended. The candidate-and-score heuristic had no model of the
problem, so every new case wanted a new branch; the scene is now one list of zones with a weight and
cost is paid per unit length inside one, which already says what a heap of special cases used to —
crossing a container's border band is dear, following it for three hundred pixels is three hundred
times dear, so a line stops disappearing into the frame without any rule about frames existing. Routes
are searched on a sparse grid with bends priced for stability, because on a hand-made layout a route
that jumps whenever a block moves is worse than one that is merely long, and ports join that grid on
their own normal, so ends come out square by construction instead of by correction. Lines still sharing
a corridor are separated afterwards, since no route computed alone can know it has a twin.

Shapes gained the same kind of self-knowledge: a shape now says where its own inside is, with an anchor
and a growth direction, instead of everything being measured from a bounding box that means nothing on
a diamond or a hexagon. The rectangle's answer is unchanged to the pixel, which is the point — this
moved knowledge, not appearance. And a hovered edge is lit from underneath rather than thickened, so a
dense diagram no longer twitches under the cursor.

## 2026-09-02

- **A sub-agent can be spawned as a named role, and the role is a boundary rather than a request.**
  A role is the settings type for an actor: its body lives in `roles/<name>.yaml` beside the manifest
  and travels in git, and `agent:` in the manifest is read as the default role, so existing projects
  mean exactly what they meant before. The manifest names the roles it accepts — a role file that
  arrives in a pull request and that nobody named does not act, which is the same rule as "no walking
  up the tree" and for the same reason. `agent_spawn` and `agent_spawn_batch` take an optional
  `role`; an unknown one is refused with the available names listed rather than quietly falling back
  to the default, because a silent fallback runs the work with the wrong capabilities and looks like
  success. When a role is named its mode governs the run and its tool selection actually narrows what
  the run is offered — a role a caller could widen by passing `mode` would not be a boundary at all,
  and a reviewer told not to fix things needs the tools withheld, not the instruction repeated. The
  narrowing is built per run through the orchestrator's tool filter, so it never touches the shared
  registry every other chat reads.

- **A spawned run is now a real, readable session instead of an in-memory record that vanished on
  restart.** It gets what every chat already had — a chat id, a file on disk, an inbox, a progress
  tree, token accounting — and `subagent.get`/`subagent.result` read that file directly rather than a
  fixed-size in-memory ring, so a client can watch one mid-run (`outcome: "running"`) and not only
  after it finishes. It stays off the ordinary chat list — `chat.list` still shows human chats only —
  and is capped instead by `agent.spawned_retention` (200 by default): the newest finished spawned
  sessions are kept and older ones ring out, but a session with a run still in progress is never
  touched, however old.

- **Two actors can now hold a correspondence and write to each other by name, instead of one side
  only ever being a task and a result.** `agent_correspond` opens an address to another role; once
  open, the chat gets its own `reply_<role>[_<topic>]` tool for that one correspondence, and the tool
  name — not a chat id in the argument list, not a line in the prompt — is the address for as long as
  the correspondence lives. Calling it returns a delivery receipt, never the correspondent's answer:
  the reply is not blocked on it, and their actual words arrive later as an ordinary message on this
  chat's own turn. A correspondent that goes quiet (archived, deleted) is announced in the chat and its
  reply tool stops appearing, rather than the next call looking like a hallucinated tool name.

- **An exchange between two correspondents now decays instead of running forever.** Nothing stops a
  reply from prompting a reply — the failure mode is two actors that never run out of things to say
  to each other on their own token budget. Four settings under `agent:`
  (`peer_debounce_base`/`peer_debounce_max`/`peer_depth_ceiling`/`peer_hard_cap`, all overridable per
  role) govern a regulator in the turn pump: the wait before waking a turn for a reply doubles with
  how many replies have already gone back and forth since a human last spoke or a background task last
  finished, up to a ceiling past which a reply no longer wakes a turn of its own — it queues and rides
  whatever turn happens for some other reason, so the conversation slows to the pace of outside events
  rather than being cut off. A hard cap exists only as an emergency stop that should never actually
  fire.

- **The chat list is a tree, and a reply now renders as speech instead of as an ordinary message from
  a stranger.** A spawned session hangs under the chat that gave it its errand, tagged with its role,
  rather than being hidden from the list or dumped in among the human chats; a sessions panel lists
  what is running — role, parent, status, model, tokens spent — across the whole tree. An incoming
  reply across a correspondence renders "from `<role>`" in its own bubble the moment it lands, live,
  and an outgoing one renders "to `<role>`" with its delivery receipt hidden — the wire message is
  still an ordinary user turn underneath, unchanged, so only the client's rendering tells the two
  apart. Opening a spawned session in its own window stays a filter over one connection, never a
  second instance, and `ui.auto_open_subagents` (off by default) is the only thing that would ever pop
  one there by itself.

- **A graph shows which actors talk to each other, and which one nobody answers.**
  Correspondences now survive a restart — they live in the chat's own session file rather than only in
  a running runtime — and each one accumulates how many replies crossed it and an estimate of their
  text. The estimate measures what actually crossed the edge rather than the token usage of the turn a
  reply happened to wake, because a turn does many things and charging all of it to one edge would be
  a confident lie. The graph is assembled from sessions on disk, so it does not change depending on
  which chats happen to be open, and each edge points from whoever invited first. The view leads with
  the imbalance rather than the picture: a role that only ever talks, and a role nobody answers.

  own caret and owns its head layout — caret, title, collapsed-only summary, actions — and panels
  supply text and buttons rather than rearranging them. A card's chrome is three variables and nothing
  else, so the redesign ahead is one class rather than a sweep through every panel.

- **The rest of the interface speaks the chosen language, through the same dictionary as the settings
  panels.** The shell and chat surfaces, the dock tabs, the workspace, the connection-lost banner, the
  plugin panels and the native window frame. The key is the English source text, so a string with no
  translation renders as English rather than as a bare key and the dictionary can be filled in without
  ever showing debris; a string arriving from the server or a plugin translates where it is drawn,
  which is why the backend needed no change at all. A sentence with inline code is one translation unit
  rather than a row of fragments, since fragments deny the translator any reordering. The Avalonia
  frame has no language setting of its own — it is told over the bridge which language the client is
  showing and rewrites its tooltips, remembering each original so the switch works in both directions.

- **The chosen language survives a restart.** It reset to English every launch, and not for want of a
  Save button: the web client is served from an ephemeral loopback port, so each launch is a new origin
  and the browser hands the page an empty `localStorage` — the choice was being saved correctly and
  then thrown away. It now lives in the machine layer (`~/.spla/defaults.yaml`, `ui.language`) and is
  carried to the client on welcome. The project manifest deliberately does not override it: a manifest
  is committed and shared, and a language is a property of the reader, not of the repository. It is not
  broadcast either, unlike appearance — on a shared server one person's pick must not retitle somebody
  else's screen. `localStorage` stays as a first-paint cache so the window does not flash English
  before the socket opens.

## 2026-09-06

- **Every correspondent has one address, and the chat it belongs to owns it.** The address used to be
  (role, topic), and the topic was free text the model retyped on every call — so a paraphrase or a
  typo silently founded a new correspondent instead of reaching the existing one. Cyrillic made it
  worse: the name normalised to a constant, several correspondents claimed the same reply tool, and
  replies went to whichever one was found first. The instance number now belongs to the chat rather
  than to a correspondence, so a third party has something it can say out loud; purpose is free text
  that explains and never addresses. `agent_introduce` connects two other chats without either side
  spelling out a chat id.

- **A model or a role can carry its own temperature and reasoning level.** An override layer between
  the project-or-machine `llm:` default and a chat's own choice: `model.temperature` slots in below
  `role.temperature`, and `role.reasoning_level` does the same for reasoning. Wired through the
  resolver, the service DTOs and both settings panels.

## 2026-09-07

- **The self-feeding guard no longer cuts off an unattended correspondence by default.**
  `ChatPump.SelfFeedingCap` was a constant fixed at 3 and counted a turn as "self-fed" even when a
  correspondent's reply was what woke it — an honest ping-pong between two roles (see the `Dialogue`
  demo project) hit the cap on the third turn, before the dedicated correspondence regulator
  (`peer_depth_ceiling`/`peer_hard_cap`) ever got the chance to act. It is now `agent.self_feeding_cap`,
  a settings field resolved the same way as the `peer_*` numbers (project, then role, override it), and
  it defaults to disabled — no cap at all — rather than 3. A project that still wants an upper bound on
  an unattended run can set a positive number to get the old behavior back.

- **A chat running as a role resolves its model through that role, not around it.** The LLM settings,
  the model entry and the reasoning capability were read from the project even when the chat had a
  role of its own, so a role naming its own connections, temperature or reasoning level was overruled
  everywhere except the few places that already consulted it.

- **A plugin's own settings keep their types on the way to the settings panel and back.** An opaque
  plugin blob is stored as YAML and handed over as JSON, and in an untyped mapping YAML has no target
  type to guide it — so `trusted_connection: true` came back as the *string* `"true"` and reached the
  plugin's bool property as JSON `"true"`, which is simply refused; numbers had the same fate. Plain
  scalars now keep the type they look like, and a quoted scalar stays the string its author asked for.

- **A window can open its own devtools, and renders at the DPI of the monitor it is actually on.**
  F12, or a button on the title bar, opens WebView2's devtools for *this* window rather than the same
  URL in a separate browser — a different process with a different profile says nothing about what
  this window is rendering. And the webview follows the monitor: a real browser window gets
  per-monitor DPI for free because it owns an HWND, while one hosted through Avalonia composites into
  the render tree and stayed at whatever scale was current when it was created, so on a mixed-DPI
  desktop it was wrong on one of the screens. The title bar also drags everywhere again, and a long
  project name clips with an ellipsis instead of pushing the buttons off the edge.

- **Popups stop hiding behind the settings overlay.** The permission and model popups are positioned
  against the body, so the in-window settings surface covered them.
