# v0.2.8

## Summary

Windows hosts now default to DPAPI secret storage and reject invalid or unavailable backends instead
of falling back to plaintext. Existing plaintext stores are not automatically migrated. Development
and tests can explicitly select the file backend at machine scope.
VisionAgent and LogSentry register DPAPI at startup, and the runtime embedding examples show
the same setup. Server builds and publishes ship the DPAPI backend from the selected build
configuration and route DPAPI read warnings to the server logger.

Claude models through OpenRouter can request prompt caching, enabled by default with a per-model
opt-out. Stable chat and spawned-run identities accompany requests, and the status bar shows
provider-reported cache reads and writes for the last call.

Roles and chats share a model picker grouped by connection, and spawned agents use the model selected
by their role. The project includes builder/tester roles for compact command reports and portable
SeMaps MCP configuration; its own MCP endpoint is configured on port 60777.

Architecture maps remain in this repository but open through the separate SeMaps application.
The bundled diagram editor, server and obsolete generator/atlas tools are removed. Release checks
stop at the first failed native command, and CI no longer calls the removed diagram checker.

## Changes

- Architecture maps now open in the separate SeMaps application instead of the bundled diagram editor.

- Claude models through OpenRouter can use prompt caching, with cache read/write token counts shown for each chat.
- Roles use the same connection-grouped model picker as chats, and spawned agents honor the role's selected model.
- The project includes builder and tester roles for concise command reports, plus shared SeMaps MCP configuration.
- Release verification stops at the first failed install, restore, build or test command, and CI no longer invokes the removed diagram checker.
- VisionAgent and LogSentry now start with the default Windows secret store.
- Server builds and publishes use the DPAPI backend produced by the selected build configuration.

## Log

## 2026-09-23

**Architecture maps now open in the separate SeMaps application instead of the bundled diagram editor.**
The workspace stays under `docs/diagrams`. `spla.semaps` and `ViewArchitecture.cmd` open it with SeMaps
on the configured port 8780. The old editor, server, atlas projects and legacy generators are removed
from this repository and its solution.

## 2026-10-15

**Windows now defaults to DPAPI secret storage and refuses unavailable or invalid backends instead of falling back to plaintext.**
Explicit `secrets.backend: file` remains available for development and tests. CLI, desktop and server
startup use the same selection policy; existing plaintext files are not read as a fallback.

## 2026-11-08

**Claude models through OpenRouter can use prompt caching, with cache read/write token counts shown for each chat.**
Caching is enabled by default and can be disabled per model with `prompt_cache: false` or in connection
settings. Chat and spawned-run identities accompany cache requests, and provider-reported cache
counters flow through token accounting to the status bar.

**Roles use the same connection-grouped model picker as chats, and spawned agents honor the role's selected model.**
The picker keeps the owning connection visible and preserves a configured model that is temporarily
unavailable. The role settings payload carries the model and connection metadata used by both pickers.

**The project includes builder and tester roles for concise command reports, plus shared SeMaps MCP configuration.**
The project manifest enables its MCP endpoint on port 60777 and includes both command-reporting roles.

## 2026-11-10

**Release verification stops at the first failed install, restore, build or test command, and CI no longer invokes the removed diagram checker.**
Native command exit codes are checked explicitly before tagging or packaging a release.

## 2026-11-11

**VisionAgent and LogSentry now start with the default Windows secret store.**
Both register DPAPI before resolving project settings. The runtime embedding examples show the same setup.

**Server builds and publishes use the DPAPI backend produced by the selected build configuration.**
Custom MSBuild output paths are supported, and DPAPI read warnings are sent to the server logger.
