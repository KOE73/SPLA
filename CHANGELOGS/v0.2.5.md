# v0.2.5

## Summary

### Reading the world: documents, spreadsheets, and finding things in files

Word documents can be read for their meaning rather than their markup — `.docx` into markdown,
plain text or a typed block tree, with no Office on the machine — and spreadsheets are addressed by
column header instead of cell coordinates, so appending a row does not depend on knowing where the
table currently ends. Alongside that, the two tools an agent actually navigates a project with were
brought up to what a person at a shell would expect: content search now has context lines,
multiline patterns and cheap files-only and count modes, and a directory listing can return the
whole tree in one call instead of one call per directory. Both changes came out of watching weak
models fail — one walked a 32,000-page reference without ever reaching the search tool, another
descended a project directory by directory — so the tools' descriptions now say when to reach for
them, not how they are built. Ripgrep ships with the agent and is resolved by an explicit path:
finding `rg` on `PATH` meant whoever could write earlier into `PATH` got to run code inside a tool
declared read-only.

### Talking to other people's tools

SPLA has served its own tools over MCP for a while; it can now consume somebody else's. A project
lists servers in its configuration, they connect at startup concurrently — one bad server cannot
take down the rest — and their tools appear in the runtime under a prefix, rebuilt whenever a
server says its list changed and torn down when it drops. The permission story is deliberately
blunt: a foreign tool declares none of SPLA's own risk axes, and guessing them from a description a
stranger wrote would hand the boundary to that stranger, so foreign tools get their own axis, are
denied in Chat and asked about everywhere else, and the grant is taken on the whole server. The
settings panel says that out loud rather than implying a finer model exists. Secrets in a server's
env or headers resolve at connect time and never travel back into settings.

### Work that outlives the turn that started it

A tool call can now run detached from the turn that issued it: the agent gets a task id
immediately and the result arrives as a message on the chat's next turn, with `task_list`,
`task_output` and `task_cancel` managing what is in flight. `system_run_shell`, `agent_spawn`,
`agent_spawn_batch`, `web_fetch` and `ssh_session_exec` opt in. A background task's progress reaches
the chat window live and survives the human's next turn rather than being cleared with it, and a
chat wakes its own turn when a result comes back. A message sent into a busy chat queues instead of
being refused, and Stop stops everything at once and says what it stopped.

### Chats, shells and the hub

A chat can be archived instead of deleted, which is what most "delete" clicks actually wanted;
delete itself now cleans up the backups and images it used to leave behind. A shell command that
goes silent no longer holds a tool call open forever — after a configurable idle period it reports
itself as still running and can be resumed — which completes the interactive-shell work from
earlier in the cycle, where a command that stops to ask a question now surfaces the question
instead of hanging. The hub can follow the operating system's light/dark setting and remembers its
own appearance independently of any project, and `spla mcp` joins an already-running instance
rather than starting a second runtime and fighting over the writer lease.

### The architecture diagram editor (experimental)

**This is an experimental feature, shipped as-is.** It is under active development, its model
contract is still moving, and neither the format nor the editor's behaviour is stable between
releases yet. It is included because it is already useful for working on SPLA's own architecture,
not because it is finished — expect rough edges, and do not build anything on the file format that
you are not prepared to migrate by hand.

With that said, it changed more than anything else this cycle. It stopped being a single
1954-line `index.html` and became a real package (`@spla/diagram`) with a canvas that can be used
on its own, then grew into a workbench: a ribbon, dockable panels that can be grouped or floated,
persistent layout, filters, theme gallery, and interface localization kept strictly separate from
the language the diagram's own data is written in. The model moved to a multi-file project format
and then to contract v3, where every translatable value records who wrote it and what it was
translated from — so a translation whose original has since changed is a finding rather than a
silent lie — and every view has to declare what its containers classify, which is what makes two
views placing the same node in different groups either legitimate or a contradiction the checker
catches. Editing caught up with the model: prose and source code can be read and written on the
element itself instead of in the JSON. Connection routing stopped guessing at geometry — a shape
now states its own safe attachment zones, which is both why parallel edges no longer collapse into
one line and how non-rectangular shapes become possible at all.

## Log

## 2026-08-24

- **Word documents can be read for their meaning, and rows can be appended to a spreadsheet by
  column name.** A new `documents` plugin (native backend: Open XML SDK + ClosedXML, both MIT, no
  Office on the machine) adds `document_extract`, which turns a `.docx` into markdown, plain text or
  a typed JSON block tree — headings, paragraphs, list nesting, tables, page breaks and image
  references, with fonts, colours and tracked changes dropped — and three spreadsheet tools,
  `spreadsheet_inspect` / `spreadsheet_read_rows` / `spreadsheet_append_rows`, that address `.xlsx`
  and `.csv` by COLUMN HEADER rather than by cell address. An append writes under the last used row
  and leaves every other cell, format and formula as it was; an unknown column is refused with the
  sheet's real columns listed rather than silently added, a `.csv`'s delimiter and encoding are
  preserved, and numbers stay numbers. The same extraction is registered into the core converter
  registry as three `(docx → markdown | text | json)` pairs, so `resource_read … as: text/markdown`
  works on a `.docx` address wherever `agent.unified_resources` is on. Which document backend serves
  those pairs is a plugin folder, not a host decision — the semantic tree
  (`SPLA.Documents.Model`) travels inside each backend, and only bytes plus a MIME type cross the
  plugin boundary. A skill, `documents.docx-to-registry`, writes the procedure down: inspect
  the target sheet first, extract, map facts to columns without inventing any, append in one call,
  read the tail back.

- **A shell command that asks a question no longer hangs forever — the agent sees the question and
  answers it.** `system_run_shell` used to return only when the process exited, so anything that
  stopped to ask (`ffmpeg` on `Overwrite? [y/N]`, `git` on credentials, an installer on
  `Do you want to continue?`) waited on stdin that nothing was connected to, holding its question in
  a pipe nobody would read until an exit that never came. The run now also returns when the command
  stops and waits: the reply carries whatever it has printed, `Status: waiting_for_input` and a
  `Session` id, and two new tools drive it from there — `system_resume_shell` sends the answer (or
  waits longer, with no input), `system_kill_shell` ends the command and everything it started.
  A question is told apart from ordinary slowness by the shape of the output: a tail with no line
  break is a prompt sitting with the cursor after it, and that is reported after two seconds, while
  total silence is reported as `Status: running` only after two minutes — so a quiet build is not
  mistaken for a question, and a question is not sat on for two minutes. `dotnet_build` and
  `dotnet_test`, which legitimately go quiet for minutes but never ask anything, keep only the
  prompt detector armed. Answering is the fallback, not the plan: the agent is told to prefer `-y`,
  `--yes` and `--force` where it knows a question is coming.

- **A tool call can now run detached from its turn.** A tool that opts in (none do yet — see below)
  reads `background: true` in its arguments, gets a `bg_N` id back immediately instead of blocking
  the turn, and keeps running; the result — success, failure, or cancellation, whichever — arrives
  as a message at the top of the chat's next turn, verified live end-to-end (schema flag reaching a
  real model, the model choosing to set it, the detached run finishing, delivery landing in the
  conversation) before this shipped. Three new tools work with it: `task_list` shows what is running
  or recently finished, `task_output` reads one task's result (repeatably — unlike the one-time
  delivery message), `task_cancel` stops one. A chat caps itself at 8 live background tasks and
  refuses the ninth rather than queuing it. A background call cannot ask a person anything —
  permission and clarification requests inside it are answered "no" automatically, since nobody is
  left to ask — so only a call that needs no mid-flight confirmation is a candidate for
  backgrounding at all. Closing a chat cancels every background task it still had running, and each
  chat's shell sessions are now its own (`ISandbox.ForChat()`) rather than shared across every open
  chat, which is what makes "close this chat, stop its work" possible in the first place.
  **Five built-in tools now opt in**: `system_run_shell`, `agent_spawn`, `agent_spawn_batch`,
  `web_fetch`, `ssh_session_exec` — the user's own call, made deliberately rather than by defaulting
  every tool in.

- **A background task's progress reaches the chat window live, and survives the human's next turn.**
  The subscription that turns `chat.Progress.NodeChanged` into `progress.node` frames moved from
  per-turn (`ClientConnection.BuildCallbacks`) to per-chat (`ChatRegistry.RuntimeOpened` →
  `SplaServiceHost.WireChatProgress`), since a detached task's tree outlives the turn that started
  it. That surfaced a collision: `ProgressTree` numbers its nodes `n1`, `n2`... starting fresh in
  each tree, so a turn's tree and a background task's tree running at the same time produced the
  same ids on the wire. Node ids are now namespaced `"{treeId}:{nodeId}"`, and `llm.turn.start`
  carries the new tree's id (`progressTreeId`) so the client knows which prefix just finished —
  it clears only that prefix from its node map on the next turn, not every node it's holding, so a
  background task's tree stays on screen across a turn boundary instead of vanishing and
  reappearing from nothing.

- **The diagram editor became a real package instead of one 1954-line `index.html`.** Markup,
  Tailwind from a CDN, styles and the whole application used to sit in a single inline script over
  twenty globals, reachable only through `onclick` attributes. It is now `tools/spla-diagram`, a
  local `@spla/diagram` package built with Vite, split along the boundary the code never had:
  `DiagramEditor` owns the catalog, inspector, toolbar, history and persistence, and `DiagramCanvas`
  underneath it owns rendering, viewport, interaction and selection — usable on its own, knowing
  nothing about `/api/save`, the catalog or undo. Extension points are registries and interfaces
  rather than a class hierarchy, so a node type or an algorithm is added without subclassing
  anything.

- **Elements resize from any edge, several can be selected at once, and typing is one undo step.**
  A selection carries eight grips — four corners and four edge midpoints, with north and west
  moving the origin so the opposite edge stays put — drawn at constant screen size so they stay
  grabbable when zoomed out. Selection is a set: Ctrl or Shift click adds and removes, Shift-drag
  on empty canvas sweeps a rubber band that takes only what it fully encloses, and clicking a
  member of a group keeps the group so dragging moves everything. With several selected, the grips
  move to the union of their boxes and dragging one maps every element into the new box. Inspector
  text edits used to mutate the model without recording anything, so undo jumped past them and
  discarded the typing; they now commit once as a single step after the field has been quiet.
  The toolbar can also switch how edge ends are placed along a side — all in the middle (the
  original behaviour, which makes parallel edges overlap exactly), spread evenly, or on a fixed
  Visio-style grid.

## 2026-08-26

- **SPLA can now consume somebody else's MCP servers, not just serve its own tools outward.** A
  project declares them in a `servers:` config section — stdio or streamable HTTP — and they
  connect at startup, concurrently, so one misconfigured or unreachable server cannot fault the
  rest. `SPLA.Mcp.Client` speaks the wire and nothing else: the transport is full-duplex frames
  rather than request/response, because a server may send a notification, or a request of its own,
  whenever it wants. A foreign server's tools are registered into the runtime under a prefix and
  rebuilt whenever that server announces its list changed; when a session drops, its tools are torn
  down rather than left showing. Secret references in a server's env or headers resolve at connect
  time only and are never written back into settings. A settings panel lists the connected servers
  with their status, tool count and a Reconnect button, and expands into a full editor where every
  env or header value is a credential field rather than plaintext.

- **A foreign tool is permitted as a stranger, on an axis of its own.** `ToolScope.Foreign` gets
  its own permission category and its own `permissions.foreign` override. A foreign tool declares
  none of SPLA's Scope/Effect/Risk axes, and inferring them from a description a stranger wrote
  would make the boundary negotiable by that stranger — so the verdict is naive on purpose: denied
  in Chat, asked everywhere else, with the existing remembered-permission mechanism turning the
  second call into an allow. Reusing `ToolScope.Internet` was rejected outright: `internet: allow`,
  set once for `web_fetch`, must not silently widen into "any foreign server may run anything".
  The grant is taken on the whole server, and the panel says so plainly next to the list.

- **An MCP client can ask the hub which projects exist before addressing one.** `POST /hub/mcp` is
  answered by the hub in-process and offers a single tool, `hub_projects_list`, returning what
  `GET /registry/projects` returns.

## 2026-08-27

- **`spla mcp` joins a running instance instead of starting a second runtime.** It previously built
  its own `AgentRuntime` and took the sole writer lease even when an instance was already running.
  It now proxies to that instance's `POST /mcp`, or spawns a child `serve --mcp` if there is none.

- **A chat can be archived instead of deleted.** Archiving moves the chat aside and closes its live
  runtime; unarchiving brings it back. The archived section is revealed by a toggle in the status
  bar, with restore and delete on each row. Delete now also removes the chat's backups and images,
  which it used to leave behind.

- **A shell command that goes quiet no longer blocks the tool call forever.** A configurable
  silent-idle timeout (`ShellTimeoutSeconds`, 120s by default, `0` disables) returns
  `Status: running` once it elapses with no output, and the caller resumes with
  `system_resume_shell`.

- **The hub can follow the operating system's light/dark setting, and remembers its own
  appearance.** The hub theme gains a system option that tracks `prefers-color-scheme` rather than
  a fixed choice, persisted independently of any project; the tray icon follows the same source.

## 2026-08-31

- **Diagram text now records where each value came from, and a view has to say what its
  containers classify.** The model contract moves to v3. Every translatable field in every
  language carries its own provenance — `authored` or `translated`, with the source language and a
  hash of the source text at the time it was translated — so a translation whose original has since
  changed is a finding rather than a silent lie. There is no base language any more: direction lives
  on each value, not on a language, which is what lets a second author write in their own tongue
  without inverting the whole project. Text catalogues cover everything nameable — containers, views,
  relations and relation types alongside entities — relation types became an authored dictionary of
  their own (`relation-types.json`), and relation prose left `relations.json` for the catalogues.
  Every view now declares a classification axis: two views on different axes may legitimately place
  one node in different containers, two views on the same axis may not, and that contradiction is
  checked. `npm --prefix tools/spla-diagram run check:model` reports stale translations, text nobody
  wrote, views without an axis, containment contradictions and broken `codeRef`s; CI runs it as a
  warning until the inherited `codeRef` backlog is cleared. The English catalogue was deleted rather
  than migrated — nobody had written it by hand and no reader needed it.

- **Container captions on the canvas show their names again instead of raw identifiers.** The
  project loader was handing a zone's caption over in `label` while the model reads it from `name`,
  so every container in every project rendered as `zone_client`, `z_llm` and the like. Zone text is
  also resolved through the container it renders (`z_x` → `c_x`), which is how the layout tool mints
  those ids.

- **A view that is missing its classification axis opens with a banner instead of refusing to
  open.** An axis is a contract the model checks, not a precondition for rendering: a project
  inherited from before v3 has views with no axis at all, and refusing them made the editor
  unusable exactly when it was most needed for the migration. The view loads, the canvas draws,
  and a banner names what is missing.

## 2026-09-01

- **Searching file content reached parity with plain grep, and one listing call can return the
  whole directory tree.** `system_search_text` gained context lines around a match
  (`context_lines`), matching across line breaks (`multiline`), and two cheaper output modes
  (`files_with_matches`, `count`) next to the default per-line content — a `max_results` now also
  bounds the work the engine does, not just the size of the answer. Engines split by substrate
  rather than by whether a binary happens to be installed: a disk-backed workspace gets ripgrep, a
  virtual one walks the logical API, and the two are held to the same semantics. `rg` ships with
  the agent and is resolved by an explicit path — a bare `rg` on `PATH` let anyone who can write
  earlier into `PATH` get executed inside a tool declared read-only, so `PATH` lookup is now
  off unless `SPLA_RIPGREP_ALLOW_PATH` turns it back on, and `SPLA_RIPGREP_PATH` overrides the
  binary. Ripgrep's stderr is read rather than swallowed, so a failure says why it fell back
  instead of degrading in silence, and the ignore glob that never matched anything is fixed.
  `system_list_files` grew `max_depth` and returns an indented tree in a single call, with
  `per_dir_limit`, `sort` and `desc` for a per-directory top-N — the tool that made weak models
  descend a project one directory per call. Both tools' descriptions now say *when to reach for
  them* rather than how they are built, which is what the two navigation incidents behind
  `ADR_20260831_mcp_search-and-listing-tools.md` actually turned on.

- **A diagram node can carry written prose, and show the source behind it without leaving the
  canvas.** A markdown editor opens on any node, zone or edge with edit / split / preview tabs and
  a per-language switch, so the description and the long text are written where the element is
  rather than in the JSON. Next to it, a code viewer resolves an element's `codeRef` and shows the
  real snippet with syntax highlighting (C#, TypeScript, JavaScript, JSON, markdown, SQL, shell).

- **Connections leave a shape from where that shape says is safe, instead of from a number the
  canvas guessed.** A renderer now answers `cornerInset(side, style)` for its own geometry, and the
  port assigners and the edge router take that inset from the two shapes being joined rather than
  from one global `cornerGap`. A line stays straight across the whole interval where the two
  shapes actually overlap and only bends into a curve when that interval runs out — previously a
  constant larger than a block's corner radius broke a straight run early, and a constant smaller
  than it parked the arrowhead on the rounded corner itself. Shapes with no rounding (UML boxes,
  and the diamonds and ellipses to come) can now answer `0` and be routed correctly without the
  canvas knowing what they are.
